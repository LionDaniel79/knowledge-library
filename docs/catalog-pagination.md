# 목록 조회 개선 검수

2026-10-14 로컬 앱에서 구현했다. 전체 서지는 DB에 그대로 두고, 소장 도서 목록은 24권씩 서버에서 검색·정렬·필터한다. 상세 원자료와 독서 세션은 책을 열 때 읽는다. 제목·저자 정렬은 DB의 일관된 문자 순서를 사용하고, 같은 값에는 식별자 순서를 적용해 페이지 사이 중복·누락을 막는다. 조회 중 책 정보가 수정되면 새로고침으로 목록을 다시 시작한다.

초기 화면에는 달력·독서 이력·메모·수동 연결에 필요한 책 요약과 첫 목록을 담는다. 서재 총 권수·분야별 권수·형태별 권수는 전체 DB 집계다. 메모의 책 선택, 사유 연결의 자료 찾기, 주제별 도서 조회도 서버 검색을 사용한다. 전체 내보내기와 복원용 백업은 목록 페이지 제한을 적용하지 않는다.

실제 데이터로 확인한 결과:

| 항목 | 확인값 |
| --- | ---: |
| 전체 도서 | 10,994권 |
| 초기 화면에 필요한 책 요약 | 464권 |
| 첫 목록 / 다음 목록 | 각각 24권 |
| 두 목록 사이 중복 | 0권 |
| 달력·메모에서 빠진 책 참조 | 0건 |
| 독서 이력 / 메모 | 419건 / 157건 |
| 기존 전체 응답 | 13,319,388바이트 |
| 개선 초기 응답 | 569,326바이트 |
| 응답 데이터 감소 | 약 95.7% |

같은 PC에서 단일 측정한 DB 읽기 시간은 초기 조회 약 1.60초, 이전 전체 조회 약 3.78초였다. 네트워크·DB 휴면 상태에 따라 달라지며 휴대폰 화면 표시 완료 시간 측정은 아니다. 실행 시 온라인 DB 변경과 외부 서지·AI 호출은 없었다.

조회 취소와 응답 순서 방어를 적용해 이전 검색의 늦은 결과가 최신 검색을 덮어쓰지 않는다. 책 목록의 원자료 생략은 저장 데이터를 삭제한 것이 아니며, 상세 조회·백업에는 그대로 포함된다. 현재 메모와 독서 이력 자체는 전체 조회한다. 이것들이 크게 늘어나면 별도 페이지 조회가 후속 작업이다.
