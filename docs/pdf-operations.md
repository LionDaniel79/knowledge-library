# PDF 색인 운영과 외장하드 저장

원본은 `E:/전자도서관`, 새 작업 위치는 `E:/지식서재 작업`이다. 페이지 색인·문자 인식 임시 이미지·PDF 첫 페이지 미리보기·서지 캐시·검수 보고서를 외장하드에 둔다. 온라인 도서 목록·메모·독서 기록과 로컬 PDF 색인은 서로 다른 보관 대상이다. 외장하드를 분리하면 로컬 PDF 검색과 원문 보기는 이용할 수 없다.

## 색인 복사와 전환

실행 중인 색인·OCR 작업을 먼저 중지한다. SQLite 온라인 백업으로 WAL을 포함한 일관된 복사본을 만들고, 무결성 검사와 주요 테이블 건수 비교를 통과한 경우에만 `.verified.json`이 생성된다. 기존 대상 색인은 덮어쓰지 않는다. 실패한 복사본을 앱에 연결하지 않는다.

```powershell
python scripts/pdf_maintenance.py copy --index "기존 색인 경로" --destination "E:/지식서재 작업/색인/pdf-library.sqlite"
```

검증 후 `LIBRARY_PDF_INDEX`를 새 경로로 바꾸고 같은 폴더의 `pdf-covers`, `bibliography-cache`, 범위 분류 보고서도 복사한다. 기존 C 색인은 복구용으로 보존한다. 같은 외장하드에 원본과 작업 파일을 두는 것은 별도 매체 백업을 대신하지 않는다.

## 재개 가능한 문자 인식

```powershell
python scripts/pdf_ocr.py --index "E:/지식서재 작업/색인/pdf-library.sqlite" --language ko --workers 2 --min-free-gb 8
```

Windows OCR은 이미 설치된 문자 인식 기능이며 폐지한 로컬 언어모델과 별개다. 원본 PDF를 수정하지 않는다. 일반 도서의 미처리 페이지만 인식하고 논문·간행물·혼합 확인 대기 자료는 기본정보만 보존한다. `--limit`으로 한 번에 처리할 페이지 수를 제한할 수 있다. 빈 결과나 오류를 다시 확인하려는 경우에만 `--retry-failed`를 지정한다.

PDF는 책별로 한 번 열고, 기존 해상도와 RGB 픽셀을 유지한 PNG를 메모리로 전달한다. 최대 두 장의 인식만 동시에 진행하며 PDF 렌더링과 DB 저장은 한 곳에서 처리한다. `--workers 1`로 메모리를 더 적게 쓰는 단일 인식 모드도 선택할 수 있다. 엔진 종료나 통신 오류는 이후 페이지를 오류로 바꾸지 않고 작업을 중지한다. PNG 압축 방식이 달라 이미지 지문이 과거와 달라질 수 있으나 결과에는 실제 전달한 이미지의 지문을 저장한다.

이미지를 보내기 시작한 때부터 응답까지 한 요청의 제한 시간은 60초다. OCR 프로세스가 이미지를 받지 않거나 응답하지 않으면 해당 프로세스를 종료하고 미완료 페이지를 남긴다. 전송 중 멈춘 경우에도 디스크 잠금을 해제하므로 다음 실행에서 재개할 수 있다.

Windows에서 다른 프로그램이 상태 파일을 잠깐 읽는 동안 파일 교체가 거부되면 최대 2초 동안 재시도한다. 상태는 완성된 JSON 단위로 교체하며, 계속되는 저장 오류는 숨기지 않는다. 이 경우에도 이미 DB에 저장한 페이지는 다음 실행에서 건너뛴다.

현재 실행이 처리 중인 페이지를 저장하고 멈추게 하려면 다음을 사용한다. 최대 두 장을 마친 뒤 멈추며 다음 실행에서 이어간다.

```powershell
python scripts/pdf_ocr.py --index "E:/지식서재 작업/색인/pdf-library.sqlite" --stop
```

OS 잠금으로 중복 OCR 실행을 막고, 페이지 단위로 저장한다. 외장하드 여유 공간이 8 GiB 미만이면 완료한 페이지를 보존하고 중단한다. 상태 파일은 색인 옆의 `.ocr-status.json`이다. 화면은 2분 넘게 갱신되지 않은 실행 상태를 ‘최근 응답 없음’으로 표시한다. 앱의 ‘상태 새로고침’으로 확인하며, 실행 재개는 현재 PC에서 위 명령으로 수행한다. 재부팅 후 자동 실행은 아직 설정하지 않았다.

## 파일 지문과 중복 감사

```powershell
python scripts/pdf_maintenance.py hash --index "E:/지식서재 작업/색인/pdf-library.sqlite" --root "E:/전자도서관"
python scripts/pdf_maintenance.py audit --index "E:/지식서재 작업/색인/pdf-library.sqlite" --root "E:/전자도서관" --output "E:/지식서재 작업/검수/pdf-audit.json"
```

SHA-256을 파일 단위로 저장하며 재실행 시 이미 계산한 파일을 건너뛴다. 읽기 전후에 크기·수정시각을 확인하고 등록한 폴더 밖의 경로는 거부한다. 기본 읽기 속도는 다른 작업에 부담을 줄이기 위해 제한한다. OCR과 지문 CLI는 공통 디스크 잠금을 사용하므로 같은 색인에서 동시에 실행되지 않는다. 다른 작업이 잠금을 점유하면 새 명령은 실패하며 기존 작업을 중단하지 않는다. 기본 문자 추출·목록 재스캔·범위 재분류는 두 작업을 중지한 상태에서 수행한다.

## 성능 비교

`scripts/benchmark_pdf_ocr.py --source "색인 경로" --output "새 비교 폴더"`는 일반 도서의 미처리 페이지만 뽑아 별도 소형 DB에 넣고 메모리 1개/2개 작업을 비교한다. 기존 방식 비교가 필요하면 변경 전 `pdf_ocr.py` 파일을 `--baseline`으로 지정한다. 원본 색인은 읽기만 하며, 각 실행의 문서·페이지별 텍스트 지문과 빈 결과까지 같아야 성공한다. 기본값은 5권×12쪽을 순서를 뒤집어 2회씩 비교한다. `report.json`의 결과를 이용하며 표본 속도를 전체 도서의 완료 시각으로 단정하지 않는다. 운영 OCR/해시를 멈춘 상태에서 비교한다.

2026-10-14 실제 도서 5권의 60쪽을 각 방식으로 두 번 비교했다. 소요 시간의 중앙값은 기존 방식 28.703초, 메모리 단일 처리 27.376초, 메모리 병렬 2개 처리 17.334초였다. 병렬 방식은 표본에서 처리량 1.66배, 소요 시간 약 40% 감소를 보였다. 총 360개 관측의 페이지별 텍스트와 빈 결과는 동일했고 오류는 없었다. 운영 색인보다 작은 별도 DB에서 측정했으므로 전체 자료에서 같은 속도를 보장하지 않으며 원문 정확성 검수를 대신하지 않는다. 상세 보고서는 `E:/지식서재 작업/검수/ocr-benchmark-20261014/comparison-01/report.json`에 보존한다.

감사 보고서의 중복 그룹은 지문이 같고 점검 시 원본의 크기·수정시각이 일치한 파일만 포함한다. 화면의 지문 개수는 저장된 개수이며 매번 모든 원본을 재검증한 숫자가 아니다. 같은 파일과 같은 판본의 종이책·PDF 관계는 다르므로 자동 병합·삭제하지 않는다. 크기와 수정시각을 의도적으로 그대로 유지한 외부 변경까지 감지하는 것은 아니다.

## 진행률 해석

- ‘본문 검색 준비’는 확인된 일반 도서 페이지 중 원본 문자 또는 OCR 텍스트가 있는 비율이다. 읽을 수 없는 파일의 미확인 쪽수는 분모에 포함할 수 없다.
- ‘문자 인식 · 원문 대조 전’은 검색할 수 있지만 사람이 인용 정확성을 검수한 것은 아니다.
- ‘빈 인식 결과’는 빈 페이지라고 확정한 것이 아니다. 원문에 글자가 있는데 인식하지 못했을 수도 있다.
- 오류·대기는 별도 집계한다. 특정 실행이 끝났다는 표시와 전체 색인 완료는 다르다.

AI 언어모델은 요청형 API만 남겼다. 일반 저장·검색·연결은 AI 호출을 만들지 않으며, 과거 로컬 분석 대기 작업을 유료 요청으로 전환하지 않는다. 삭제가 보류된 모델 파일은 실행하지 않는다.
