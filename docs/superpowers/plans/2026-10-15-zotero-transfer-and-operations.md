# Zotero 전송과 운영 편의 구현 계획

> For agentic workers: use superpowers:executing-plans. 승인된 남은 작업을 직접 순차 구현한다.

**Goal:** 실제 서지 전송·중복 방지·충돌 확인과 PC 재시작 후 재개를 사용 가능한 상태로 만든다.
**Architecture:** 기존 책·Zotero 연결·작업 이력 테이블을 사용한다. PC의 암호화 키는 서버에서만 읽는다. 미리보기 후 최대 50권씩 명시적으로 전송하며 PDF·메모·독서기록은 제외한다. 기존 자료 수정은 앱이 이전에 전송한 서지의 버전이 일치할 때만 허용한다.
**Spec:** docs/research-and-zotero.md, docs/next-implementation-roadmap.md 및 사용자의 주요 남은 작업 계속 진행 요청.
**Tech Stack:** Next.js, PostgreSQL, TypeScript, Zotero Web API v3, Windows PowerShell.

## 제약과 판단
- 기존 feat/library-mvp 작업을 이어가며 기존 수정과 실행 중 OCR을 보존한다.
- 새 비밀키·새 외부 서비스·유료 AI 호출·PDF 전송 없음.
- 사용자는 서지를 보고 전송을 선택한다. 실제 대량 전송은 구체적 미리보기를 준비한 뒤 이전의 '연결 확인만' 승인 범위와 구분한다.
- 단방향 서지 갱신: 외부에서 수정·삭제한 자료는 충돌로 표시하고 자동 덮어쓰거나 부활시키지 않는다.
- 불확실한 제목 유사도는 자동 병합 근거가 아니다. 같은 ISBN도 상이한 서지는 검토 대상으로 남긴다.
- 외부 웹 게시, 사용자 정답 평가, 다른 기기의 VPN 연결은 이 구현으로 완료했다고 표시하지 않는다.
