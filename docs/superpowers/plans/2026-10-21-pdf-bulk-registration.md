# PDF 일괄 등록 구현 계획

Spec: ../specs/2026-10-21-pdf-bulk-registration-design.md

## Task 1: 로컬 작업 및 파일 조사

- SQLite 작업/파일 체크포인트, 원자적 실행 임대와 중지/재개를 구현한다.
- Python의 기존 분류·색인 스키마를 재사용하여 안전한 조사·해시·앞뒤 추출·개별 색인 명령을 제공한다.
- 테스트를 먼저 실패시킨 뒤 빈 색인 생성, 재개, 경로 경계, 중복 처리 동작을 검증한다.
- Expected: 작업 저장소와 Python fixture 테스트 통과.

## Task 2: 등록·서지 보완 작업자와 API

- 기존 importPdfCatalog 및 변경 추적 트랜잭션을 사용한다.
- 이미 등록된/제외된 자료와 내용 변경 자료를 보존한다. 정확한 ISBN 판본만 자동 보완하고 후보는 별도 저장한다.
- detached worker, 소유자 인증·출처 검사, Vercel 실행 차단, 오류 재시도를 구현한다.
- 연결 GET의 기존 자료 필수 조건을 제거하고 빈 폴더 최초 연결을 지원한다.
- Expected: 실제 PGlite 등록·중복·제외·재개 및 API 경계 테스트 통과.

## Task 3: 사용자 화면과 설치 문서

- 연결 검사 / PDF 일괄 등록 버튼, 조사 결과·진행·중지/재개·재시도·검토 후보를 표시한다.
- 완료 후 기기의 변경분 동기화를 시작하고 새 목록을 반영한다.
- 최초 설치 준비, 기본 등록/색인/서지/OCR의 차이와 제한을 짧게 문서화한다.
- Expected: 합성 E2E 데스크톱·모바일 검수 통과.

## Task 4: 전체 검수와 배포

- unit/typecheck/E2E/build/artifact privacy 검사를 실행한다.
- 하나의 독립 최종 검토를 받고 중요한 문제를 회귀 테스트와 함께 해결한다.
- 기존 승인 범위대로 GitHub·웹·PC 릴리스에 반영하고 실제 설정창을 확인한다. 실제 소장 자료 등록을 테스트 명목으로 실행하지 않는다.

Review focus: 재시작/동시 실행의 중복 방지, 제외 원본의 이름 변경, 루트 이동과 임의 폴더 혼동, 비밀정보·서버 전용 경로 노출, SQLite와 온라인 DB 사이의 재실행 안전성, 사용자 편집 경쟁, 클라우드에서의 실행 불가, 대량 작업의 메모리/출력 제한.
