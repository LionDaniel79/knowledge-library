# OCR 처리 속도 개선 검수 기록

## 적용한 변경

- 같은 PDF를 페이지마다 다시 열지 않고 책 단위로 재사용한다.
- 기존 해상도와 RGB 픽셀을 유지한 이미지를 메모리로 전달한다. 운영 경로에서는 임시 PNG를 디스크에 저장하지 않는다.
- 최대 두 개의 Windows OCR 프로세스가 인식하고, 결과는 문서·페이지·원본 변경 여부를 확인한 뒤 한 곳에서 저장한다.
- OCR과 파일 지문 계산은 같은 색인에서 동시에 실행하지 않는다.
- 전송과 응답을 합친 60초 제한 시간을 넘기면 해당 OCR 프로세스를 종료한다. 완료한 페이지는 보존하고 미완료 페이지는 재시도 대상으로 남긴다.
- 원본 PDF, 기존 문자 텍스트, 논문·간행물 제외 정책은 유지한다. 새 언어모델이나 유료 API를 사용하지 않는다.

## 성능과 검증

일반 도서 5권에서 12쪽씩, 같은 60쪽을 세 방식으로 두 번씩 비교했다. 두 번째 비교는 실행 순서를 뒤집었다.

| 방식 | 소요 시간 중앙값 |
| --- | ---: |
| 기존 임시 파일 방식 | 28.703초 |
| 메모리 단일 처리 | 27.376초 |
| 메모리 병렬 2개 처리 | 17.334초 |

병렬 방식은 이 표본에서 처리량이 1.66배였고 소요 시간은 약 40% 줄었다. 360개 관측의 페이지별 텍스트와 빈 결과가 모두 같았으며 오류는 없었다. 비교용 DB는 운영 DB보다 작으므로 전체 서재에서 동일한 배율을 보장하지 않는다. 결과 일치는 원문 정확성을 사람이 검수했다는 뜻이 아니다.

독립 검토에서 전송 단계의 무한 대기 가능성 1건을 발견했다. 이미 준비 신호를 보냈지만 입력을 읽지 않는 실제 자식 프로세스로 실패를 재현한 뒤 제한 시간을 전송 단계까지 적용했다. 수정 후 페이지 보존과 잠금 해제도 확인했다. 미룬 검토 지적은 없다.

최종 코드 검증: 마지막 운영 보완 후 Python 29개, 앱 단위 테스트 138개 모두 통과. 브라우저 화면이나 배포 설정은 변경하지 않았다.

## 운영 확인

기존 OCR의 실행 중 처리량 21,354쪽을 보존하고 교체했다. 남은 파일 지문 49개를 재개해 오류 없이 마쳤다. 이어서 읽기 전용 감사에서 등록 파일 9,309개 모두 저장된 지문과 현재 크기·수정시각이 일치하며 지문 미계산 파일이 없음을 확인했다. 기존 PDF 열기 오류 90개는 별도 검토 대상이며 이번 속도 개선으로 해결했다고 보지 않는다.

실제 운영 색인에서 100쪽을 처리하고 지정한 한도에서 정상 정지했다(텍스트 97쪽, 빈 인식 3쪽, 오류·원본 변경 0건). 2026-10-14 17:21:39 KST에 재개했고 추가 119쪽 저장 후 상태 파일 교체가 Windows의 일시적인 읽기 잠금과 겹쳐 중단됐다. 저장된 페이지는 유지됐다. 실제 열린 파일 핸들로 이 충돌을 재현하고, 최대 2초 재시도와 계속되는 잠금의 명시적 실패를 검증했다. 빈 인식은 실제 빈 페이지라고 확정한 것이 아니다.

보완 후 17:26:21 KST에 작업을 재개했다. 17:26:49의 77쪽에서 17:27:20의 151쪽으로 저장량이 늘었고, 오류 0건·오류 로그 0바이트였다. 관리 프로세스 1개와 그 자식 OCR 프로세스 2개만 실행 중임을 확인했다. 당시 세 프로세스의 작업 집합 메모리 합계는 약 227 MiB였으며 계속 변할 수 있다. 실행 상태와 검증 기록은 외장하드의 `production-verified.json`에 남겼다. 전체 OCR 완료가 아닌, 개선한 처리 방식으로 정상 재개한 상태다.

## 구현 중 판단과 비용

1. 기존 기능 개발 작업 폴더를 재사용했다. 실행 작업이 이 경로에 의존하므로 경로를 유지했다. 다른 변경과 섞이지 않도록 수정 범위를 한정해야 하는 비용이 있다.
2. SSD 임시 이미지 대신 메모리 이미지를 선택했다. C 드라이브와 외장하드 임시 쓰기를 줄이는 대신 최대 두 장의 이미지와 프로세스 간 전송을 위한 메모리를 사용한다.
3. 검토에서 발견한 전송 제한 시간 문제를 이번 범위에서 수정했다. 요청마다 짧게 실행되는 전송 스레드 하나가 추가된다.
4. 운영 검증에서 새로 드러난 Windows 상태 파일 잠금 충돌도 안정적인 재개 범위에 포함해 수정했다. 일시적인 저장 충돌 때 최대 2초 대기하는 비용이 있다. 검토 의견 수정과 별개로 발견한 운영 문제이며 추가 리뷰 라운드는 열지 않았다.

코드는 현재 로컬 기능 브랜치에 보존한다. 재부팅 후 자동 실행은 이번 작업에 포함하지 않았다. 비교 원자료와 운영 로그는 `E:/지식서재 작업/검수/ocr-benchmark-20261014` 및 `E:/지식서재 작업/logs`에 보관한다.
