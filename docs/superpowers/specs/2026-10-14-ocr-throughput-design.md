# OCR 처리 속도 개선

사용자가 승인한 방향: PDF를 책별로 한 번 열어 연속 처리하고, 임시 이미지 저장을 줄이며, 인식은 두 작업으로 나누고 결과는 순서대로 저장한다. 중복 검사와 디스크 경합도 줄인다. 현 PC는 6코어/12스레드, RAM 약 16GB이며 원본과 색인은 외장 HDD에 있다.

PDF 렌더링은 메인 실행 흐름에서만 수행하고 최근 책 하나를 유지한다. 기존 해상도·RGB 픽셀을 유지한 무손실 PNG를 메모리에서 생성한다. 최대 두 장만 대기시키며 각각 독립된 Windows OCR 프로세스로 전송한다. 결과 수집·SQLite 쓰기·쪽 번호 및 파일 서명 검증은 한 곳에서 순서대로 수행한다. 새 모델 설치나 AI API 호출은 없다.

Windows OCR의 기존 파일 입력은 호환성을 위해 유지하되 새 경로는 PNG 바이트를 받는다. 결과 이미지 지문은 실제 전송한 PNG에 해당한다. 기존 기록을 다시 쓰거나 인식된 원문을 검수 완료로 표시하지 않는다. 논문·간행물, native text 및 이미 인식된 페이지는 기본 처리에서 제외한다.

원본 변경·범위 변경·엔진 종료·낮은 저장 공간·중단 요청을 검사한다. 엔진 전체 장애는 이후 페이지를 실패 처리하지 않고 멈춘다. 완료한 페이지는 개별 커밋하고, 대기 중 최대 두 장은 중단 시 다시 처리할 수 있다. 새 실행은 요청한 PID가 같은 중단 파일만 수락한다. OCR와 해시 CLI는 색인별 공통 디스크 잠금으로 동시에 실행하지 않는다.

검증은 변경 전과 같은 원본 페이지를 별도 소형 색인에 넣고 한 작업/두 작업의 실행 시간을 비교한다. 텍스트·원본 페이지 대응·픽셀 동일성을 확인하고 실제 운영 재개 및 저장된 처리 건수 증가까지 확인한다. 기존 작업 중지·재개는 승인된 성능 개선의 일부이며, 원본 삭제·외부 전송은 하지 않는다. 성능 배수는 측정 후에만 보고한다.
