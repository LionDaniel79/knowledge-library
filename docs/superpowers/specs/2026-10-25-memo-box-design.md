# 독서 메모 상자 설계

## 의도와 사용자 선택

사용자는 독서 중의 생각을 기록하고, 상자처럼 주제로 모으고, 연결을 다시 읽으며 내용을 다듬어 책·글에 활용하려 한다. ‘목차를 만들고 메모를 순서대로 모아 글감으로 내보내기까지’를 선택했다. AI의 자동 판단·대필은 추가하지 않는다. 원문·내 생각·메모 연결 이유·글을 위한 해석을 구분한다. 특정 역사 인물의 독서법을 재현했다고 단정하지 않는다.

## 비교한 접근과 결정

- 기존 기록·주제·연결·연구 배치를 재사용하는 ‘메모 상자’: 자산이 복제되거나 별도 메모 체계로 갈리지 않고 기존 기기 저장과 이력을 사용할 수 있다. 이 방식을 구현한다.
- 새로운 독립 노트/집필 DB: 기능 중복과 재동기화가 필요해 현재 목적과 11/1 검수 보류에 맞지 않는다.

사용자는 계획 후 구현까지 직접 요청했고, 이전에 직접 순차 구현·정상 GitHub/웹 반영을 지시했다. 기능 범위 선택은 위 선택으로 확정했다. 실제 DB/기기 동기화 검수는 11/1로 보류한다.

## 사용자 화면

상단 메뉴는 **주제별 자료 | 화이트보드 | 메모 상자 | 설교·논문 자료 | 새로고침 | 사용법**이다. 생각의 흐름·검토할 후보·사유의 연결의 독립 화면·메뉴를 제거한다. 기존 메모·주제·연결·판단 이력은 지우지 않고 재사용한다.

1. 주제별 자료: 자료 종류·분야·주제·정렬의 폭을 줄이고 표시 개수 바로 왼쪽에 검색 입력을 둔다. 검색은 제목·메모 본문·책 정보 범위이며 기존 필터와 함께 적용한다. 전체 결과에서 검색·정렬한 다음 페이지를 나눈다. 휴대폰에서도 검색과 표시 개수 순서를 유지한다.
2. 모든 기록 작성/수정 창: 태그 바로 위에 검색형 복수 주제 선택. 새로운 기록에서도 선택 가능하다. 연결할 책과 검색 결과 사이의 여백은 실제 측정 후 대략 1/3로 줄이고, 조회 상태는 줄 높이를 흔들지 않게 표시한다.
3. 메모 상자: PC는 목록/세부사항, 휴대폰은 한 열. 내부에 연결된 메모 / 연결된 주제 / 글감 엮기 세 가지 보기가 있다. 검색·분할 목록을 지원하고 전체 원문을 미리보기로 덮어 저장하지 않는다.

### 연결된 메모

- 화이트보드가 만든 실제 accepted 메모 관계를 사용한다. 기록을 선택하면 연결된 다른 기록·관계 종류·연결 이유를 표시한다.
- ‘기록 수정’은 기존 전체 기록 편집기를 연다. 연결의 관계/이유는 기존 editConnection과 버전 검사로 수정한다. 출처·쪽수는 필요할 때 펼친다.
- ‘관련 기록 남기기’는 선택한 기록을 원본으로 연결한 새로운 내 기록을 만든다. 선택한 주제를 미리 넣되 사용자가 바꿀 수 있다. 출처 메모의 본문은 자동 복사하지 않는다.

### 연결된 주제

- accepted 주제 연결, 화이트보드의 topic 묶음 연결, 서로 다른 주제의 실제 메모 연결을 근거별로 표시한다. 단순 단어 유사도로 관계를 추론하지 않는다.
- 주제 쌍을 선택해 각각의 설명과 관련 메모를 보고 수정한다. 관련 새 기록은 두 주제로 분류한다. 관계 근거가 여러 개이면 구분해 보여 주며 일괄 해제하지 않는다.
- 삭제 주제/휴지통 기록/거절한 연결은 제외한다. 책에서 이어받는 주제는 기록의 명시적 거절을 존중한다.

### 글감 엮기

- 기존 library_research / items / placements 저장을 재사용한다. 현재 서버 CHECK가 sermon/thesis이므로 일반 글감은 기존 thesis 연구·집필 분류를 쓰고 UI에서 ‘집필·논문’으로 일관되게 표시한다. 새 DB 스키마는 추가하지 않는다.
- 제목·중심 질문·한 줄에 하나씩 목차를 작성한다. 목차는 연구 질문의 사람이 읽을 수 있는 Markdown ‘## 목차’ 절로 보존하고 UI에서 다시 분리한다. 기존 묶음은 그대로 읽는다. 길이 검사를 한다.
- 메모를 골라 출처·당시 버전과 함께 담는다. 원문은 기존 snapshot에 보존하며 이후 수정과 구분된다. 메모별 장/절·역할·순서·나의 해석을 수정한다. 위·아래 이동은 두 자료를 버전 검사 후 한 명령에서 교환한다.
- Markdown 글감 문서, 일반 텍스트, 기존 서지 내보내기를 제공한다. AI가 완성한 글로 표시하지 않는다. 메모 내용과 나의 해석, 출처를 구분하고 삭제/제외 자료를 임의 복원하지 않는다.
- 묶음 제목·질문·목차 수정은 기존 값의 비교 조건을 사용하고 기존 revisions에 이력을 남긴다. source snapshot/version 확인, 중복 담기 방지도 재사용한다.

## 저장과 신뢰성

- noteInput에 선택적 topicChanges [{topicId,status,expectedVersion}]와 relatedNotes [{noteId}]를 추가한다. 메모 저장·주제 배정/해제·관련 연결을 한 트랜잭션에서 처리한다. 기존 호출이 이 필드를 생략하면 기존 메타데이터는 그대로 둔다. 같은 주제의 중복 변경은 거절한다.
- topicChanges는 전체 목록 교체가 아닌 사용자가 바꾼 부분만 전달한다. 다른 기기의 분류를 조용히 지우지 않는다. 활성 주제/기록과 소유권, 관계 자기 연결을 검사한다.
- 하위 행 ID는 requestId+종류+배열 위치로 결정해 기기와 서버가 같은 ID를 사용한다. 소스 ID가 바뀌어도 ID가 달라지지 않는다. 참조는 topicId/noteId 객체 필드를 사용해 기존 참조 치환에 맞춘다.
- 기기 저장에서도 같은 효과를 한 번에 만든다. 즉시 기기에 기록하고 온라인 전송은 기존 큐가 담당한다. 화면은 네트워크 동기화를 기다리지 않는다. 실제 큐 전송/기기 간 검사는 지금 실행하지 않고 11/1에 추가한다.
- 새 기록 주제 조회는 소량의 주제·해당 기록의 분류만 반환한다. 메모 상자는 열 때 기존 whiteboard snapshot과 소량의 주제 상세/관계를 재사용하며 모든 도서 본문·PDF를 내려받지 않는다.

## 검증

실제 사용자 자료로 시험하지 않는다. 순수 모델/고립 PGlite/모의 브라우저로 검색 교차 조건·주제 atomicity·권한/버전/중복·원문 보호·신규 관련 기록·주제쌍 근거·목차 읽기/저장/글감 이동/내보내기·모바일 폭/높이·제거 메뉴를 확인한다. OCR와 PC PDF 서버는 유지한다. E의 단일 저장소 별도 브랜치에서 작업한다. 새 개발 사본이나 대규모 백업을 만들지 않는다.
