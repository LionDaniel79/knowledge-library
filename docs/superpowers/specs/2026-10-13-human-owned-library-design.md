# 내가 쓰고 판단하는 지식서재 — 개발 중 자료 정비와 운영 중 최소 AI

작성일: 2026-10-13. 상태: 사용자가 선택한 방향을 구체화한 설계·구현 계획 초안. 이번 요청의 산출물은 계획이며, 이 문서를 작성하면서 앱 코드·실제 자료·API 설정을 바꾸지 않는다.

## 1. 사용자의 목적과 시점

사용자는 ‘로컬 처리 + 필요할 때 GPT API’ 방식을 선택했다. **AI를 많이 쓰는 시점은 지금 진행하는 개발과 기존 자료 정비 과정이다. 앱을 처음 실행하는 시점이 아니다.** 완성된 서재는 평생 읽고, 자기 문장으로 기록하고, 직접 연결하고 판단하는 도구다. 기록량이나 자동 생성량보다 다시 찾을 수 있는 자기 생각이 중요하다.

따라서 개발 중 AI가 자료의 정돈을 돕고, 운영 중에는 사람이 글과 판단을 남긴다. 개발 중 이 대화의 Codex가 자료 진단·분류체계 초안·태그 정비·정리 스크립트 작성에 적극 참여한다. 별도 GPT API로 대량 처리하는 것은 별개의 비용·실행 경로다. ‘AI를 많이 쓴다’는 말을 곧바로 유료 API 대량 호출 지시로 해석하지 않는다.

기존 승인 설계 중 ‘로컬 생성 모델로 계속 생각 변화를 추론’, ‘메모를 저장할 때마다 자동 비교’, ‘작업기 시작 시 전체 기록 재분석’은 이 문서로 대체한다. 원문 검증, 수정 이력, 사용자 확인, 분야 안·분야 사이 검색, 기존 자료 보존은 계속 적용한다. PC에서의 공개 모델 성능 시험 결과는 과거 실험으로 남긴다.

## 2. 개발 중 할 일과 완성 후 할 일

| 영역 | 지금 개발 과정 | 완성 후 일상 사용 |
|---|---|---|
| 도서 목록 | 서지 오류·누락·중복 후보 조사, 출처 기반 보완 | 직접 추가·수정, 필요한 서지 조회 |
| 분야·태그 | AI로 검색용 분류·개념·동의어·태그 후보 정비 | 기존 태그 선택·수정, 원할 때만 제안 받기 |
| PDF | 추출 상태 진단, 제목·목차·구절을 이용한 검색 색인 구축 | 검색·원문 열기·하이라이트·직접 메모 |
| 기존 메모 | 원문 보존, 관련 주제·날짜 오류·인용 혼재 후보 표시 | 직접 쓰기, 인용과 내 생각 구분, 수정 이력 |
| 사유의 지도 | 찾기 쉬운 관련 자료 후보 준비 | 두 기록을 직접 연결하고 관계·이유 작성 |
| 설교·논문 | 관련 자료를 찾을 수 있는 기반 정비 | 사용자가 자료 선택·논지 구성·출처 확인 |
| AI | Codex의 개발 지원과 필요시 비용 제한 API 일괄 작업 | 버튼을 누른 선택 자료에 한정한 보조 |

앱의 최초 실행 마법사, 시작 시 전체 정리, 일상 메뉴의 대규모 ‘AI 정리 센터’, 자동 설교·논문·독서 감상 생성은 만들지 않는다. 새 책을 추가할 때도 가져오기·서지 조회·색인 갱신과 유료 생성 분석을 분리한다.

## 3. 자료는 세 층으로 구분한다

### 원자료

PDF 원본·쪽별 추출문·iReadItNow 가져오기 원문·공식 서지 출처. 원본 파일은 덮어쓰지 않는다. PDF 본문 페이지 번호와 파일 페이지 번호를 구분하고, 확인되지 않은 인쇄 쪽수를 추정하지 않는다. 종이책은 본문이 없으면 서지·목차·직접 기록만으로 정리하며 읽지 않은 본문을 읽은 것처럼 요약하지 않는다.

### 검색을 돕는 정리 정보

검색용 주제·별칭·태그·자료 소개·비슷한 자료 후보·서지 수정 후보. AI/규칙/서지 공급자 중 누가 만들었는지, 어떤 원문 범위를 봤는지, 언제 어떤 버전으로 만들었는지 기록한다. AI 결과를 보조 색인에 일괄 저장해 검색에 사용할 수 있다. 표시는 ‘정리 태그’, ‘정리용 소개’, ‘관련 자료’이며, 사용자는 숨기거나 고칠 수 있다.

### 내가 남긴 기록과 판단

사용자가 직접 쓴 메모·감상·질문·주장·반론·성찰, 선택한 개인 태그, 확정한 관계와 판단 이유. AI는 이 영역의 글을 자동 작성·수정하지 않는다. 사용자가 AI 제안을 채택해도 원래 제안 출처와 채택 이력은 남는다. ‘확인했다’와 ‘직접 작성했다’를 같은 속성으로 저장하지 않는다.

세 층은 통합 검색에서 함께 찾을 수 있지만 결과에 출처를 표시하고 ‘내 기록만’ 필터를 제공한다. AI가 쓴 소개를 내 메모 수·독서 기록 수에 포함하지 않는다.

## 4. 지금 수행할 기존 자료 정비

지난 2026-10-13 조사 기준 목록 10,994건(iReadItNow 1,685건, PDF 목록 9,309건), 메모 157건, 제안 주제 30개가 있다. 목록 건수는 중복을 제거한 고유 도서 권수가 아니다. 실행 직전에 다시 집계한다. PDF 범위는 사용자가 지정한 `E:\전자도서관`으로 유지한다. `sources/` 동기화 자료는 읽기 전용이다.

1. **현황과 복구 지점:** 현재 목록·개인 기록·분류·수정 이력을 백업한다. PDF 파일 존재·변경·추출 상태, 누락 서지, 출처 미확인 태그를 집계한다. 원문 전체를 진단 보고서나 Git에 넣지 않는다.
2. **분류체계:** 공식 KDC와 개인 관심 주제를 분리한다. 기존 제안 주제 30개와 실제 자료에서 출발해 신학·상담·철학·과학·문학 등의 주제·하위 주제·동의어를 정돈한다. 분야 간 연결을 위해 자료에는 복수 주제를 허용한다. 추정 분류를 공식 KDC로 표시하지 않는다.
3. **표본 60건:** 서지·PDF 자료 30건, 기존 메모 20건, 중복·판본·OCR·분류 모호 사례 10건을 겹치지 않게 선정한다. 원문을 보고 정리 방식을 검수한다. 이 단계는 Codex가 이 개발 대화에서 지원할 수 있다. API를 쓰는 경우 전송 범위·예상 비용·한도를 보고 실행한다.
4. **정비 결과 파일:** AI가 만든 후보는 ID·원문 버전·근거를 포함한 비공개 정리 파일로 저장하고 스키마·원문·소유자 검증기를 통과시킨다. 직접 SQL로 제안을 본문에 덮어쓰지 않는다.
5. **단계적 확대:** 검증된 정리 방식을 100건 단위로 적용한다. 오류율·확인 필요 건수·처리 범위·비용을 남기고 재개할 수 있게 한다. AI 결과는 보조 색인에 저장하므로 사용자가 수천 건을 전부 승인해야 검색이 가능해지는 구조를 피한다.
6. **서지와 중복:** 정확히 일치하는 판본의 공식 출처만 검증된 사실로 취급한다. 사람 손으로 수정한 필드는 보존한다. AI가 ISBN·분류번호·저자·발행년을 생성해 빈칸을 채우지 않는다. 동일 파일은 해시로 판정하되 파일을 삭제하지 않고, 다른 번역·판본·종이책/PDF 소장 형태는 자동 병합하지 않는다.
7. **검수와 이관:** 분류·태그의 표본 품질을 확인한 뒤 결과를 앱의 검색 자료로 반영한다. 개발 정비 작업은 종료 상태로 봉인하고 실행 파일·자료 범위·복구 정보를 남긴다. 사용자 앱의 시작이나 배포가 이 작업을 다시 실행하지 않는다.

AI 정리 태그는 규칙으로 표기를 통일하고 중복을 줄일 수 있다. 개인 태그의 일괄 변경·주제 병합은 변경 미리보기와 사용자 선택을 거친다. 기존 태그의 생성 경위를 확실히 알 수 없으면 `legacy_unknown`으로 보존하며 ‘사람이 작성’ 또는 ‘AI 작성’으로 소급 단정하지 않는다.

157개 메모의 발화 주체는 아직 확인 전이다. AI가 인용 가능성을 표시할 수 있지만, 내 생각·책 인용·작성 시점을 자동 확정하지 않는다. 인용과 감상이 섞인 원문은 그대로 보존하고 사용자가 선택한 구절로 인용 또는 별도 생각을 만들 수 있게 한다.

## 5. 완성 후 기본 사용 흐름

**책 찾기 → 읽기·원문 확인 → 내 문장으로 기록 → 태그·책장 선택 → 관련 기록을 열어 직접 연결 → 필요시 생각의 변화 기록.**

- 기록 저장은 그 자체로 성공한다. AI 응답이나 모델 설치가 필요하지 않다.
- 저장·수정·페이지 진입·앱 시작·작업기 연결로 GPT 호출이나 생성 분석 작업을 등록하지 않는다.
- 글을 작성하는 화면은 빈 입력란에서 시작한다. AI가 문장이나 해석을 먼저 채워 넣지 않는다.
- 제목·저자·분야·태그·내 기록·PDF 발췌 검색은 기존 색인으로 실행한다. 로컬 의미 검색은 선택 기능이며 기본 키워드 검색은 모델이 없어도 작동한다.
- ‘관련 자료 보기’는 저장된 태그·어휘·기존 벡터를 사용한다. 유사성을 근거·동의·반론·입장 변화로 표시하지 않는다.
- 새 자료의 규칙 기반 파싱·전체 텍스트 색인 갱신은 허용하되, 새 임베딩 계산은 별도 로컬 작업으로 분리하고 메모 저장을 막지 않는다.
- 책 내용과 내 견해, 문서 수정과 생각의 변화, 완독 횟수와 읽은 분량을 계속 구분한다.

### 사유의 지도

기본은 주제별 내 기록과 시간순 보기다. 사용자가 두 기록을 선택하고 ‘유지·확장·수정·입장 전환·비교 어려움’ 및 자기 이유를 적어 연결한다. AI가 만든 비교와 수동 연결을 모두 지원하되 출처를 표시한다. 날짜 미상 기록도 읽고 관련 자료로 연결할 수 있으나 앞뒤가 확정된 변화처럼 그리지 않는다.

‘그때의 생각’과 ‘지금의 생각’을 나란히 열어 사용자가 새 성찰을 작성할 수 있다. 과거 메모를 고친 것만으로 새로운 생각 변화 사건을 만들지 않는다. 지도에서 책은 근거·독서 맥락으로 연결하고 ‘이 책 때문에 생각이 바뀌었다’는 판단은 사용자가 적는다.

### 남길 AI 보조 기능은 세 가지

| 기능 | 입력 | 결과 | 저장 방식 |
|---|---|---|---|
| 태그 제안 | 사용자가 선택한 기록 1개 | 기존 주제 체계 안의 태그 최대 5개 | 선택한 태그만 개인 기록에 반영; AI 출처 유지 |
| 선택 구절 설명 | 선택한 발췌 최대 3개 | 짧은 설명과 원문 근거 | 별도의 보조 결과 카드. 내 메모 자동 생성 없음 |
| 두 기록 비교 도움 | 직접 선택한 기록 2개 | 공통점·차이·비교 후보와 근거 | 검토 대기. 관계·이유 확정은 사용자만 |

세 기능 모두 명시적 요청 때만 호출한다. 개인 기록의 상시 요약, 자동 감상문, 지도 선 자동 확정, 독서 때마다 알림, 모든 기록 재분석 버튼은 운영 기본 기능에서 제외한다. 도움 기능을 꺼도 기본 독서·기록·검색·지도·설교/논문 자료 모음은 사용할 수 있다.

## 6. 처리 위치와 비용

첫 구현은 기존 PC 작업기를 활용하는 로컬 처리 구조를 유지한다. 일반 규칙 처리와 선택적 검색 임베딩은 PC, 어려운 설명·비교만 GPT API다. 공개 소형 생성 모델을 계속 상주시켜 개인 입장을 판단하게 하지 않는다. GPT API 후보는 GPT-6 Luna이며 이 서재의 한국어 표본 평가를 통과해야 사용한다. 모델명·프롬프트·스키마·사용 토큰·호출 출처를 기록한다.

운영 흐름: `웹앱에서 선택·요청 → 소유자 전용 요청 대기열 → PC가 필요한 원문 확보 → GPT API → 구조·원문 검증 → 보조 결과 동기화 → 사용자 선택`.

PDF와 API 키는 PC에 보관한다. 온라인 DB에는 목록·개인 기록·검색용 정리 정보·출처·요청 상태·사용자가 볼 결과를 저장한다. PC가 꺼졌을 때 새 GPT 보조 작업은 대기하며, 온라인에 저장된 기록과 결과는 조회할 수 있다. 클라우드에서 직접 처리하는 최적화는 이후 별도 검토한다. PC 연결 파일에는 API 키를 넣지 않는다.

정비 작업용 GPT API 비용과 일상 보조 API 비용은 따로 집계한다. 이 대화의 Codex 사용량과 별도 API 청구도 구분한다. 현재 사용자는 자료 정비의 시점을 정정했으며 **달러 예산은 정하지 않았다**. 따라서 문서 작성·소스 확인·정리 방법 설계는 진행하되 별도 API 실행 한도는 미설정 상태다. API 키·한도 없이는 호출하지 않는다. 이 계획 작성 중 실제 GPT API를 호출하지 않는다.

운영은 동시 요청 1개, 요청마다 범위와 출력 길이 제한, 결과 캐시, 같은 버전 요청의 중복 방지를 적용한다. 월별·작업별 남은 예산을 호출 전에 예약하고 사용량으로 정산한다. 통신이 끊겨 과금 여부를 모르면 예약을 유지하고 자동 재호출하지 않는다. 예산 초과·모델 불가·PC 대기는 기록 저장 실패와 별도로 표시한다.

## 7. 데이터 모델과 변경 이력

기존 `library_books`, `library_notes`, `library_topics`, `library_topic_memberships`, `library_connections`, `library_thought_events`, `library_evolution_candidates`, `library_analysis_feedback`를 재사용한다. AI 보조 결과를 개인 메모 테이블에 저장하지 않는다.

| 추가 데이터 | 필수 내용 |
|---|---|
| `library_ai_policy` | owner, runtimeMode=`manual_only`, 요청 허용 여부, 개발/운영 비용 한도(미설정 허용), 버전 |
| `library_curation_runs` | owner, 개발 정비 실행 ID, 자료 범위의 해시, 실행자, 시작/완료, 상태, 복구 보고서 |
| `library_curation_items` | 원자료 ID·버전, 필드/종류, 제안값, 근거, coverage, 작성 주체(rule/Codex/API/provider), 사용 여부, 사용자 결정 |
| `library_field_origins` | 대상 ID·필드, human/imported/official/ai/rule/legacy_unknown, 작성 원천, 확인자·시각, 이전 이력 |
| `library_assist_requests` | owner, 요청 ID, 목적, 선택 자료·버전, 정책 버전, 대기/처리/완료/오류/취소, 임대, 연결 기기 |
| `library_assist_results` | request ID, 결과 유형, 원문 근거, model ID·prompt/schema 버전, 검증 상태, 사용자 채택 이력 |
| `library_ai_usage` | request/정비 항목 ID, 개발/운영 구분, provider request ID, 입력·출력·추론·캐시 토큰, 예약·실제 비용, 확정/미확정 |

`coverage`는 `metadata / toc / partial / full`을 유지한다. 목차·일부 구절만 처리하고 책 전체 분석으로 표시하지 않는다. 공식 서지 검증 여부와 사용자 확인 여부는 별도 속성이다. 사람이 AI 문구를 수정해 채택한 결과에도 파생 출처를 남긴다.

기존 비교 큐는 운영 전환 때 미처리 자동 생성 건을 `superseded`로 보존하고 새 요청을 만들지 않는다. 실행 중 작업은 정책 버전 변경으로 결과 반영을 차단한다. 이미 확정한 사용자 판단·과거 후보·수정 이력은 삭제하지 않는다. 새 보조 요청은 명시적 요청 전용 별도 대기열로 기존 자동 큐와 섞이지 않게 한다.

## 8. 개인정보·원문·품질

원문 파일 전체 대신 작업에 필요한 메타데이터·목차·선택 발췌만 전송한다. 작업 미리보기에서 전송할 자료를 확인할 수 있다. 파일 경로·로그인 토큰·관련 없는 기록을 프롬프트에 넣지 않는다. 서지 조회는 출처의 실제 응답으로 검증하며 AI가 만든 URL을 근거로 취급하지 않는다.

GPT 응답은 Structured Outputs로 받되 거절·불완전 응답·스키마 오류·원문 불일치를 보류한다. 형식이 맞는 것과 판단이 맞는 것은 별개다. 모델에 DB 수정·파일 조작·인터넷 탐색 도구를 주지 않는다. 자료 안의 지시문은 데이터로 취급한다.

API에는 `store:false`를 사용한다. 이는 데이터가 전혀 보관되지 않거나 ZDR이 된다는 뜻은 아니다. 공식 문서상 API 자료는 명시적 동의가 없으면 모델 학습에 사용되지 않지만, 기본 오용 모니터링 보관 등은 별도로 적용된다. 책 원문·개인 기록·키·정리 결과 파일은 Git에 넣지 않는다.

## 9. 검수 기준과 범위

- 개발 정비 적용 전후 개인 메모 본문·작성일·독서 이력의 의도하지 않은 변경 0건.
- 앱 첫 실행·메모 저장/수정·화면 진입·작업기 재시작으로 발생한 GPT 호출 0건.
- 승인하지 않은 개인 관계 확정 0건, 다른 소유자 자료 노출 0건, 출처 없는 공식 서지 확정 0건.
- 표시하는 인용은 100% 실제 원문·페이지·버전과 검증. 확인되지 않은 날짜·발화 주체는 그대로 유지.
- 개발 표본 60건 중 분류·태그 유용성 사람 검수 90% 이상을 확대 기준으로 제안한다. 프로젝트 기준이며 모델의 일반 성능 주장이 아니다. 애매한 건은 보조 정보로 남겨도 된다.
- 서로 다른 분야·미분류·다른 판본·부정 표현·인용 혼재를 포함한다. 운영의 두 기록 비교는 사용자 검수 30쌍으로 평가하고, 그 정확도를 전체 서재에 일반화하지 않는다.
- 비교 보조의 잠정 운영 기준은 원문·날짜·발화 주체 검증 100%와 30쌍 중 사람 검수 유용성 90% 이상이다. 기준 미달 또는 미검수이면 비교 보조를 켜지 않고 수동 기능은 계속 제공한다.
- 새 정리 전후 동일한 검색 질문 최소 20개로 관련 자료 상위 결과와 누락 여부를 비교한다. 직접 쓴 기록의 검색 노출이 나빠지면 정리 태그 가중치를 적용하지 않는다.
- API가 꺼지고 PC가 연결되지 않아도 온라인 메모 저장·키워드 검색·수동 지도·자료 모음이 정상 동작해야 한다. 오프라인 웹 편집 전체를 보장한다는 뜻은 아니다.
- JSON/Markdown 내보내기는 원자료 참조, 개인 기록, 보조 정보, 판단·수정 이력을 구분한다. AI를 끊어도 축적된 자산을 다른 도구에서 읽을 수 있어야 한다.

## 11. 개발 중 추가된 전체 자료 정비 범위 (2026-10-13)

사용자 지시로 iReadItNow 목록 전체와 E:/전자도서관의 PDF 전체를 조사한다. 다만 PDF 중 논문·간행물은 기본정보(제목, 저자, 발행정보, 페이지 수, 파일 위치)만 유지하며 본문 추출/OCR/본문 검색/AI 문맥/목차·소개·리뷰 보강에서 제외한다. 종이책과 일반 도서의 정비는 계속한다. 강해집·성경 주석서는 일반 도서로 포함한다. 책과 논문이 섞인 자료는 확인 전 metadata_only로 보류하며, 혼합 폴더 전체를 논문이라고 확정하지 않는다. 이미 저장된 추출문은 백업에 보존하고 운영 검색·분석에서는 차단한다. 원본 PDF와 개인 기록은 변경하지 않는다.

목차는 실제 목차/북마크 또는 판본이 확인된 출처에서 가져온다. 출판사 소개와 독자 리뷰는 근거를 구분해 간결하게 재서술하며 개인 독서 메모로 저장하지 않는다. 자동화로 알 수 없는 내용은 채워 넣지 않는다. 출처 URL·수집일·판본 일치·근거 문장은 저장하되 기본 화면에서는 접힌 ‘근거 보기’로 제공한다.

알라딘 공식 고객센터에 2026-10-30 OpenAPI 종료 공지가 있어 신규 핵심 의존성으로 채택하지 않는다. Open Library는 대량 API 수집 대신 공식 덤프 정책을 따른다. 키나 이용 권한이 필요한 자료는 미연결 상태를 정직하게 기록하고 가능한 작업을 먼저 진행한다.
