# 사유의 지도: 내 생각의 변화

> **2026-10-13 방향 변경:** 아래 문서는 이전 합의의 기록이다. 이후 사용자는 ‘지금 개발 중 AI로 자료 정비, 일상은 직접 작성·판단, 필요할 때만 GPT API 보조’를 선택했다. 로컬 생성 모델 상시 비교·저장 시 자동 분석 부분은 [새 설계](2026-10-13-human-owned-library-design.md)와 [구현 계획](../plans/2026-10-13-human-owned-library.md)으로 대체한다. 원문 검증·수정 이력·사용자 확정·분야 간 검색은 유지한다.

상태: 2026-10-13 사용자가 설계대로 진행하도록 승인했다. 같은 날 추가한 분야·주제별 탐색과 사용자 피드백 활용 요구를 아래에 반영했다. 세부 구현 계획 작성 단계이며 AI 기능은 아직 구현하지 않음.

## 합의한 목적과 선택

- 1순위는 시간이 지나면서 자신의 생각이 어떻게 바뀌었는지 돌아보는 것.
- 같은 주제의 기록을 시간순으로 놓고 AI가 유지·확장·수정·입장 전환 후보와 근거 문장을 제시한다.
- 책의 주장과 독자의 입장을 구분한다. 사용자가 확인한 변화만 확정한다.
- AI는 내 PC에서 실행하고 결과를 온라인 개인 서재에 동기화한다. PC가 꺼져 있으면 새 분석은 대기한다.
- 기존 소장 도서·메모·인용·수정 이력은 그대로 사용한다. 일반 업무 프로젝트 관리로 확장하지 않는다.
- 방대한 자료를 분야·주제로 구조화하고 같은 분야 안과 분야 사이에서 모두 연결을 찾는다. 사용자의 승인·거절·수정을 다음 추천 개선에 활용한다.

## 분야·주제·개념을 통한 탐색

책의 공식 서지 분류(KDC)와 독자가 생각을 정리하는 주제 체계를 별도로 연결한다. 공식 분류 하나로 책의 모든 구절이나 독자의 관점을 규정하지 않는다. 예를 들어 `종교 > 기독교 윤리`, `철학·심리학 > 상담`에 속한 자료가 공통 개념 `용서`로 만날 수 있다.

- 탐색 화면은 분야 → 주제 → 개념 순서로 펼친다. 주제는 대표 상위 주제 하나를 갖고 다른 분야·주제와의 연관선을 별도로 갖는다. 여러 분야에서 같은 개념으로 접근할 수 있다.
- 책·내 기록·PDF 구절은 여러 주제에 연결할 수 있다. 미분류 자료도 검색한다. 책장(읽을 목록, 인생 책)과 분야·개념은 서로 다른 용도로 유지한다.
- 처음에는 기존 태그·서지·목차에서 후보를 만들고 문맥 검색으로 보완한다. 자동 제안·사용자 확인·공식 서지 확인을 구별하고, 주제명·별칭·연결을 수정하거나 제외할 수 있게 한다.
- 주제 카드는 이름, 별칭, 짧은 사용자 정의, 대표 원문 발췌, 관련 자료 수를 보여 준다. AI 요약만을 근거로 연결하지 않는다. 목차만 읽은 책은 `목차 기반`, 일부 페이지만 처리한 책은 `부분 분석`, 원문 없는 종이책은 `서지·내 기록 기반`으로 표시한다.
- 같은 주제, 인접 주제, 전체 자료에서 찾은 후보를 함께 비교한다. 카테고리는 탐색 우선순위이며 자동 탐색에서 자료를 완전히 제외하는 조건이 아니다. 사용자가 명시적으로 분야 필터를 선택한 경우에만 범위를 제한한다.
- 처음에는 각 경로에서 최대 20개를 찾고 중복·동일 판본 편중을 줄인 뒤 재정렬한다. 최종 비교는 기록 2개와 선택적인 맥락 자료 최대 4개로 제한한다. 수치는 검증할 초기 설정값이지 정확도를 보장하는 비율이 아니다.
- 분야 간 연관선에는 그 선을 뒷받침하는 실제 자료 쌍을 함께 보관한다. 많이 등장한 분야가 모든 연결을 차지하지 않도록 분야별 결과 분포와 미분류 결과를 평가한다.

## 사용자 피드백과 모델 학습

강화학습은 기술적으로 가능하지만 현재 CPU·16GB PC의 첫 구현 범위는 검색·추천 개인화다. 모델 추론이 가능한 것과 모델 가중치를 학습시키는 것은 필요한 자원이 다르다. 강화학습의 반복 생성·보상 계산·가중치 갱신 비용을 고려해 로컬 LLM 강화학습을 기본 실행하지 않는다.

1. 승인·거절·수정 및 이유, 당시 원문 버전, 모델·검색 설정을 저장한다. 판단 철회도 이력으로 남긴다.
2. 확인한 주제·별칭, 거절한 자료 쌍, 좋은 비교 사례를 다음 검색과 프롬프트에 반영한다. 이는 모델 가중치 학습과 구분해 표시한다.
3. 관련성 피드백이 충분해지면 CPU에서 작은 추천 순위 모델을 시험한다. 초기 실험 시작 기준은 관련성 판단 100건과 별도 검증 30건이며, 데이터가 부족하면 기존 검색을 유지한다. 이 기준은 프로젝트 운영 기준이며 보편적 필요 학습량은 아니다.
4. 장기적으로는 사용자가 교정한 출력으로 SFT/LoRA, 같은 입력에 대한 선호·비선호 출력이 갖춰지면 DPO를 비교할 수 있다. DPO는 별도의 온라인 보상 탐색을 수행하는 강화학습과 구분한다. GRPO/PPO 등은 보상 기준·GPU 자원·검증 데이터가 확보될 때 별도 실험으로 검토한다.

`관련 없음`, `근거 부족`, `변화 유형이 틀림`, `내 생각이 아닌 인용`, `중복`을 구별한다. 의견이 다르다는 이유만으로 관련성을 낮추지 않는다. 반론을 찾을 능력을 유지한다. 모델이 만든 후보를 사용자 정답으로 재활용하지 않는다. 시간대·도서·유사한 기록 묶음을 분리해 평가 자료가 학습 자료에 섞이지 않게 한다.

검증된 좋은 비교 사례를 최대 2개 참고시키되 정답을 복사하게 하지 않는다. 사례도 입력 토큰 예산에 포함한다. 학습용 내보내기는 별도 요청 시 개인 기록·확인한 판단 중심으로 만들고, 책 원문 전체나 저작권이 불명확한 본문은 기본 포함하지 않는다. 외부 학습 서비스로 자동 전송하지 않는다.

## 사용자 경험

1. 생각이나 독서 메모를 저장하면 `비슷한 과거 기록 찾는 중`으로 표시한다.
2. 주제를 선택하면 예전 기록 → 관련 독서·인용 → 최근 기록 순서로 읽는다. 날짜가 불분명한 가져온 기록은 `날짜 미확인`으로 구분하고 인과관계를 만들지 않는다.
3. 후보 카드에는 두 시점의 내 문장, 날짜, 관련 책·원문 페이지, AI의 짧은 비교 설명을 나란히 보여 준다.
4. `유지 / 확장 / 수정 / 입장 전환 / 비교 어려움` 중 AI가 제안한 관계를 직접 고치고 `확인`하거나 `관련 없음`을 선택한다. 인용만으로 사용자의 동의나 입장 전환을 추정하지 않는다.
5. 확인된 흐름을 타임라인으로 표시한다. 지도의 선은 출발 기록에서 이후 기록으로 향한다. 책과 구절은 맥락 자료로 연결하고, 사용자 확인 없이 변화의 원인이라고 표시하지 않는다.
6. 기존 기록을 편집하는 것은 문서 수정 이력이다. 그것만으로 사상이 변한 사건을 만들지 않는다. 사용자가 별도 성찰을 남기거나 과거 버전 비교를 요청할 때만 변화 후보로 다룬다.
7. 확정·거절·수정은 취소 또는 재검토할 수 있고 이전 판단도 보관한다.

## 비교한 실행 방식

| 방식 | 장점 | 한계 | 결정 |
|---|---|---|---|
| PC에서 분석, 결과 동기화 | 모델 이용료 없음, 원문과 메모를 외부 AI에 보내지 않음 | PC 실행·인터넷 연결 필요, CPU 처리 속도 제한 | 사용자 선택 |
| 외부 무료 API | PC가 꺼져 있어도 사용 가능 | 무료 한도·모델 변경·개인 기록 전송 및 데이터 사용 조건 | 현재 미사용 |
| PC와 외부 AI 선택형 | 요청별 유연성 | 설정과 개인정보 전송 판단 복잡 | 현재 범위에서 제외 |

## 모델과 실행 가능성

확인한 PC: Ryzen 5 5600G, 메모리 약 16GB, AMD 내장 그래픽. 별도의 NVIDIA GPU 및 Ollama 설치는 확인되지 않았다. GPU 가속을 가정하지 않고 CPU 기준으로 측정한다.

- 관련 기록 검색 후보: **Qwen3 Embedding 0.6B**. Apache 2.0, 다국어 의미 검색 모델. 공식 모델 카드에 MTEB 평가가 공개되어 있다. 8B 모델의 순위를 0.6B 모델의 성능으로 소개하지 않는다.
- 기록 비교 후보: **Gemma 4 E2B의 4비트 양자화 모델**부터 시험한다. E2B는 실제 전체 가중치가 단순 2B보다 크므로 모델명만으로 메모리 사용량을 계산하지 않는다. E4B는 E2B의 한국어 비교 성능이 부족하고 메모리 여유가 확인될 때만 비교한다.
- 모델은 웹앱 JavaScript에 넣지 않는다. 별도 로컬 실행기에 내려받아 실행하고 지식서재와 연결한다. 모델 버전·다운로드 출처·파일 해시·라이선스를 기록한다.
- 초기 입력은 메모 2–6개, 최대 약 4천 토큰, 결과는 짧은 구조화 데이터로 제한한다. 검색 모델과 비교 모델을 동시에 메모리에 올리는 것을 기본으로 하지 않는다.
- 설치 전 다운로드 용량과 여유 디스크를 확인한다. 실제 측정 전 실시간 응답 초수나 처리량을 보장하지 않는다.
- 공개 벤치마크는 후보 선정 근거이며 신학·상담·철학 메모의 입장 변화 판정 정확도를 보장하지 않는다. 자체 한국어 검수를 통과해야 활성화한다.

## 처리 구조

`기록 저장 → 변경 기록 대기열 → PC 작업기 → 관련 과거 기록 검색 → 두 기록 비교 → 인용 검증 → 후보 저장 → 웹앱 표시 → 사용자 확인`

- 온라인: 현재 인증 계정, 도서·기록, 분석 작업 상태, 사용자에게 표시할 후보·확정 관계를 저장한다.
- 로컬: PDF 원본·추출 원문·검색 벡터·모델 가중치·작업 캐시를 저장한다.
- 기존 로컬 웹앱에서는 로컬 작업기가 기존 서버 DB 연결을 사용한다. 인터넷 배포 후에는 소유자에게 한정된 작업 API와 기기 인증을 별도 구현한다. 공개 웹앱에 관리자 DB 접속 정보를 넣지 않는다.
- PC가 외부로 연결해 작업을 가져오는 방식이다. PC의 추론 포트를 인터넷에 열지 않는다.
- 절전·종료·외장하드 미연결 시 멈춘 사유를 표시한다. 이미 저장된 지도와 결과는 계속 조회할 수 있다.
- PC 작업기는 5초 간격으로 새 작업 확인을 시작하되, 유휴 상태에는 간격을 늘린다. 웹앱은 진행 중에만 상태를 확인한다. 실제 DB 무료 한도와 부하를 측정해 주기를 조정한다.
- 동시에 분석 1건만 실행한다. 사용자가 누른 분석을 기존 PDF 전체 분석보다 우선한다. 반복 요청은 같은 기록 버전과 모델 버전으로 중복 제거한다.

## 데이터와 안전장치

- `topics`: 주제명, 별칭, 사용자 확인 여부.
- `topic_memberships`: 책·기록·구절과 여러 주제의 연결, 근거·출처·확인 여부·거절 이력.
- `topic_links`: 주제 사이의 연관, 이를 뒷받침하는 자료 쌍, 사용자 판단.
- `analysis_feedback`: 당시 후보·입력 버전·승인/거절/수정 이유·수정한 출력. 관련성과 입장 일치를 별도 판단으로 보존한다.
- `thought_events`: 기록 ID·버전, 원래 작성일, 내 생각/책의 인용 구분, 주제 ID.
- `evolution_candidates`: 이전·이후 기록 ID와 버전, 제안 관계, 양쪽의 정확한 근거 문자열 및 위치, 간단한 설명, 모델·프롬프트 버전, pending/accepted/rejected/stale, 사용자 판단과 수정 이력.
- `analysis_jobs`: 소유자, 요청 자료의 버전, 작업 종류, queued/running/completed/failed/waiting_for_pc, 시도 수, 임대 만료 시각, 오류 사유. 중단된 작업은 임대 만료 뒤 재개하고 결과 저장은 멱등 처리한다.
- 근거는 실제 저장된 기록의 부분 문자열과 일치해야 한다. PDF 인용은 기존 파일 서명·페이지 검증을 사용한다. 없는 문장·쪽수·원인을 생성한 후보는 표시하지 않는다.
- 분석 중 원문이 수정되면 예전 결과는 stale로 남기고 확정하지 못하게 한다. 확정 시에도 버전을 다시 확인한다.
- 메모와 PDF 안의 명령은 자료로만 취급한다. 모델에 파일 삭제·웹 호출·DB 변경 도구를 주지 않는다.
- 낮은 유사도, 상반된 날짜, 인용과 입장의 혼동은 `비교 어려움`으로 종료할 수 있다. 자동 확정은 없다.

## 단계와 검수

1. **로컬 성능 시험**: 모델을 설치하고 실제 기록의 소량 표본으로 소요 시간·최대 메모리·한국어 설명·근거 일치율을 측정한다. 처음에는 DB에 관계를 쓰지 않는다. 30쌍 이상의 평가 목록에 무관한 기록·인용·부정문·동일 주장·달라진 관점을 포함한다. 사용자가 확인한 정답을 기준으로 평가한다.
2. **시간순 보기**: AI 없이도 날짜·태그·주제로 내 기록을 읽고 수동으로 변화를 연결한다.
3. **분야별 검색과 변화 후보**: 주제 안·인접 주제·전체 자료의 어휘/의미 검색 결과를 합쳐 비교한다. 검색 경로를 설명하고 후보의 모든 근거 문자열은 100% 원문 일치해야 한다. 확정 전 사용자 확인은 필수다.
4. **자동 분석·동기화**: 기록 저장 후 분석, 재시도·절전 복구·다른 기기 요청과 상태 표시. 인터넷 배포 여부는 별도 확인한다.
5. **PDF 맥락 확장**: 내 생각의 변화에 실제로 관련된 책 구절을 연결한다. 9천 개 PDF의 모든 페이지를 첫 단계부터 의미 색인하지 않는다.

검수에는 다른 계정 접근 차단, 중복 요청, PC 중단·재시작, 오래된 기록 버전, 거절 후보 재등장 방지, 판단 수정 이력, 네트워크 단절, 원문 근거 없는 응답 거절을 포함한다. 속도는 측정 결과로 사용자에게 제시하고, 대기 시간 허용 범위를 그 뒤 확정한다.

검색은 기존 공통 단어 방식, 분류를 쓰지 않는 의미 검색, 분야·주제 경로를 합친 검색을 같은 평가 자료로 비교한다. Recall@20(관련 자료를 놓치지 않는 정도), Precision@5(상위 결과의 관련성), 분야 간 연결 발견, 잘못된 생각 변화 판정, 보류 비율, 처리 시간·메모리를 함께 기록한다. 근거 문장이 정확하다는 것만으로 AI 해석까지 정확하다고 판단하지 않는다.
