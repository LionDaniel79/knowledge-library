# iReadItNow HD 자료 이전

2026-10-13 업데이트. 실제 iPhone 백업에서 iReadItNow HD의 SQLite와 표지를 복구했고, 사용자가 확인한 소장 도서 1,685권을 온라인 서재에 반영했습니다. 아래의 원래 조사 경로는 이후 다른 백업을 다룰 때 참고합니다.

## 이번 이전 결과

- 도서 1,685권: 확인된 종이책 474권, 전자책 633권, 원본에 형식이 없는 578권. 형식 누락을 종이책이나 PDF로 추정하지 않았습니다.
- 내용이 있는 기록 157건: 메모 27건, 서평 130건. 빈 서평 3건은 원본 테이블에 보존했습니다.
- 독서 세션 428건과 책갈피 1,570건은 책별 원본 기록으로 보존합니다. 상태 코드의 의미가 확인되지 않아 일반 독서 회차/완독 통계에는 합산하지 않습니다.
- 표지 1,684개 레코드에서 중복 이미지를 합쳐 1,676개 파일을 보관합니다. 현재 표지는 로컬 서버에서 소유자 인증 후 제공합니다. Vercel에서는 이 PC의 폴더에 접근할 수 없으므로 별도 비공개 파일 저장소가 필요합니다.
- 동일 묶음 재검사에서 새로 추가할 도서/기록 0건을 확인했습니다. 재가져오기는 원본 ID가 같은 자료를 건너뛰어 사용자 편집을 보존합니다. 원본 앱에서 내용이 바뀌어도 자동으로 덮어쓰지 않습니다.

## 사용 방법

1. 원본 SQLite와 같은 이름의 `_SUPPORT/_EXTERNAL_DATA` 폴더를 함께 보존합니다. 계정 DB는 변환 대상이 아닙니다.
2. `python scripts/convert_ireaditnow.py --help`로 인자를 확인해 새 출력 폴더에 변환합니다. 원본은 읽기 전용으로 열며 기존 출력 폴더를 덮어쓰지 않습니다.
3. 변환된 `ireaditnow-library.json`을 앱의 ‘기존 자료 가져오기’에서 선택하고 미리보기를 확인한 뒤 가져옵니다. 화면 업로드 한도는 4MiB입니다.
4. 표지 표시를 위해 서버의 `LIBRARY_IMPORT_ASSET_DIR`에 변환 폴더의 `assets` 절대 경로를 지정합니다. 개인 JSON·SQLite·이미지를 Git에 넣지 않습니다.
5. 로컬 검수는 `node --import tsx scripts/import-ireaditnow.ts <JSON> --verify-local`, 실제 DB 미리보기는 `node --env-file=.env.local --import tsx scripts/import-ireaditnow.ts <JSON>`입니다. `--apply`를 붙이면 확인된 소유자 계정으로 저장합니다.

변환 묶음은 일반 서재 내보내기와 다른 형식입니다. 날짜 누락·미확정 상태를 사용자가 앱 원본과 대조한 뒤 정식 독서 회차로 옮기는 단계는 후속 작업입니다.

이번 자료의 메모에는 사진 첨부가 없습니다. 다른 백업에 포함된 사진 메모는 파일 보존까지 지원하지만 앱에서 사진을 보여 주는 화면은 후속 범위입니다.

## 확인한 사실

- [공식 App Store 설명](https://apps.apple.com/kr/app/ireaditnow-hd/id765221261)은 서버 자동 백업과 여러 기기의 동기화를 명시합니다.
- 같은 공식 페이지의 버전 1.1.6 이력에는 ‘노트 이메일로 보내기’가 나옵니다. 현재 앱에서 모든 기록을 일괄 보낼 수 있다는 뜻은 아닙니다.
- 공개된 HD 전용 API 또는 현재 작동하는 전체 내보내기 경로는 이번 조사에서 확인하지 못했습니다.
- 구형 일반판의 웹 내보내기 주소에 관한 오래된 안내는 HD 호환성/현행 서비스 여부의 근거가 아닙니다. 해당 도메인의 현재 접속도 확인되지 않아 로그인 정보를 입력하도록 안내하지 않습니다.

## 권장 진행 순서

1. **현재 앱과 기록 보존**: 동기화를 고치기 위해 앱을 삭제하거나 재설치하지 않습니다. 기존 기록을 보유한 기기를 유지합니다.
2. **PC 기기 백업**: Windows의 Apple 기기 앱으로 iPhone/iPad를 백업합니다. [Apple 공식 절차](https://support.apple.com/en-us/108967). 백업 비밀번호는 사용자가 직접 보관합니다.
3. **앱 자료 포함 여부 조사**: 백업 사본의 Manifest에 iReadItNow HD 영역이 있는지, DB/JSON/이미지 자료가 포함되는지 읽기 전용으로 확인합니다. 앱이 해당 파일을 백업에서 제외했다면 포함되지 않을 수 있습니다. 암호화된 백업은 정상 암호 해제가 필요합니다.
4. **변환 가능한 경우**: 앱의 실제 스키마를 확인한 다음 10~20권만 시험 변환합니다. 책/읽기 상태/시작·완독일/메모/밑줄/쪽수/원본 식별자를 분리하고 원본을 유지합니다.
5. **백업에 없는 경우**: 앱 내 개발자 문의로 본인 계정의 서버 자료를 CSV/JSON 또는 백업 파일로 제공할 수 있는지 요청합니다. 연락 가능 여부나 응답은 보장할 수 없으며 이 작업에서 메시지를 전송하지 않았습니다.
6. **대안**: 앱이 제공하는 노트 공유 자료 또는 목록/상세 화면을 OCR로 읽고 사람이 검토합니다. 목록 화면만으로는 모든 메모와 읽기 날짜를 복원할 수 없으므로 마지막 수단으로 사용합니다.

## 가져오기 구현 규칙

- 원본 파일 해시, 출처 앱, 원본 ID, 변환기 버전, 가져온 날짜를 보존합니다.
- 누락된 날짜를 오늘 날짜로 채우거나 책 내용을 추정하지 않습니다.
- ISBN과 판본, 제목·저자·출판사 비교로 중복 후보를 제시합니다. 자동 병합하지 않습니다.
- 표지·메모 이미지는 원본 경로 및 해시로 연결합니다.
- 독서 회차와 단순 상태 값을 구분합니다. 회차를 알 수 없으면 ‘날짜 미확인 완독’으로 별도 검토합니다.
- 한 건의 재실행이 중복 저장되지 않도록 원본 앱/ID 기반 가져오기 키를 둡니다.
- 가져오기 미리보기에서 건수·오류·중복·필드 대응을 확인한 뒤 확정합니다.
- 총 책 수와 상태별/연도별 집계, 무작위 원문 대조, 누락 메모 검사를 통과한 다음 전체 이전을 진행합니다.

이번 백업은 변환·이관을 완료했지만 다른 버전의 앱 DB까지 호환된다고 보장하지 않습니다. 원본 스키마를 먼저 확인하고, 원본 백업은 계속 보관합니다.


## 2026-10-13 독서 이력 확인

사용자 대조로 전체 완독 415회와 현재 읽는 4권을 확인하고 정식 독서 회차로 변환했습니다. 세션 상태 2와 종료일을 완료로, 도서 상태 4의 최신 진행 세션을 현재 독서로 해석합니다. 2026년 날짜가 있는 완료는 27회이며, 사용자가 원본 앱 화면에서 확인한 25.5권은 별도 연간 통계로 보존합니다. 수치를 맞추기 위한 날짜 변경·회차 삭제는 하지 않았습니다. 원본 ID 기반 재실행은 이미 가져온 회차 및 사용자가 수정한 날짜를 덮어쓰지 않습니다.
