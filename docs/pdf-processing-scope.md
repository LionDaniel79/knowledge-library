# PDF 자료 처리 범위

2026-10-13 사용자의 최종 정정: **논문과 간행물은 기본정보만 보관한다. 강해집·성경 주석서는 제외하지 않는다.**

- 기본정보: 제목, 저자, 확인된 발행정보, 페이지 수, 파일 위치 및 파일 식별값. 모르는 서지는 추측해 채우지 않는다.
- 논문·간행물: 새 본문 추출, OCR, 목차 수집, 상세 소개·리뷰 보강, 본문 검색 및 AI 문맥 제공에서 제외한다. 직접 파일을 여는 기능과 사용자가 이미 작성한 메모는 유지한다.
- 일반 도서(강해·주석 포함): 색인·목차·출처 기반 보강 대상이다.
- 책과 논문이 섞여 판별할 수 없는 자료는 `review`로 표시하고 기본정보만 유지한다. 폴더명만으로 일반 도서를 논문으로 확정하지 않는다.

`scripts/pdf_scope.py`의 규칙은 파일 경로와 기존 제목만 사용한다. 원문을 열어 분류하거나 AI로 확정하지 않는다. 자동 판별의 결과이며 완벽한 문헌 유형 분류라는 뜻은 아니다. `scope_override`가 설정된 수동 판단은 재분류가 덮어쓰지 않는다.

## 적용 경로

로컬 SQLite의 `processing_scope/material_kind/scope_reason/scope_version`을 온라인 `library_documents`에 동기화한다. 오래된 미분류 색인은 본문 조회를 허용하지 않는다. 작업 대기열뿐 아니라 직접 페이지 처리 호출, 검색, 상세 목차, AI 참고 문맥, 자료 보강 저장에서도 범위를 확인한다. 범위를 다시 포함시키면 `metadata_only` 상태에서 색인을 재개할 수 있다.

기존 추출 데이터는 복구를 위해 보존하며 제외된 자료의 기존 본문은 운영 검색·분석에 노출하지 않는다. 원본 PDF는 수정하지 않는다. 적용 전 백업을 만들었고 도서·개인 메모·독서 이력이 변경되지 않았는지 비교했다. 출처와 파일 위치 등 상세 정보는 기본 화면에서 접어 둔다.

## 운영 명령

Python 환경에 `pypdfium2`가 필요하다. 실제 색인 경로는 `LIBRARY_PDF_INDEX`로 관리하며 개인 경로를 저장소에 넣지 않는다.

```text
python scripts/pdf_library.py scope --index <색인 파일>
python scripts/pdf_library.py basic --index <색인 파일>
node --env-file=.env.local --import tsx scripts/import-pdf-catalog.ts --apply
python scripts/pdf_library.py work --index <색인 파일> --page-budget 120 --min-free-gb 8
```

`work`는 일반 도서의 아직 처리하지 않은 페이지부터 이어 간다. 여유 공간 8 GiB 미만이면 중단한다. OCR이 필요한 빈 페이지를 읽은 것처럼 취급하지 않는다. 동시에 같은 색인에 둘 이상의 작업기를 실행하지 않는다.

## 실제 적용 결과

2026-10-13 규칙 v2026-10-13.3 기준 PDF 9,309개: 일반 도서 4,066개, 논문 2,607개, 간행물 2,599개, 혼합 자료 확인 대기 37개. 이는 자동 분류 결과이며 작업 완료 권수가 아니다. 온라인 범위 동기화 후 도서 10,994건·메모 157건·독서 회차 419건은 백업과 동일했다.

전체 서지·목차·소개 보강과 OCR은 별도 진행 작업이다. 현재 범위 변경이 그 작업의 완료를 의미하지 않는다. 비용이 드는 AI API 호출은 하지 않았다.
