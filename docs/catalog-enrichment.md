# 서지정보 보완과 분류 기준

책 분야는 한국십진분류법(KDC) 큰 분류 000–900을 사용한다. 기존 태그·폴더·제목으로 제안한 분야는 `검토 필요`이며, 도서관에서 실제 조회한 분류번호와 구별한다. `100 철학·심리학`은 사용자가 찾기 쉽게 표기한 이름이며 KDC 정식 대분류명은 철학이다.

## 현재 수집 방식

- `npm run catalog:collect -- --online --limit 5`: 도서관 정보나루에서 같은 ISBN의 서지·분류·표지 정보를 조회하고 미리 검사한다. `--apply`를 붙여 검증된 제공자 정보를 별도 보조 정보로 저장한다. 한 번에 최대 100권이며 중단 후 다시 실행할 수 있다. `--google`은 별도 키를 사용하는 Google Books 보완 조회다.
- 온라인 조회는 ISBN 또는 도서 제목을 전송한다. 개인 메모와 PDF 본문은 전송하지 않는다. ISBN별 응답은 `CATALOG_CACHE_DIR`에 보관하고 다시 사용한다. 미설정 시 Git에서 제외한 `private-data/catalog/`를 쓰며, 현재 PC는 `E:/지식서재 작업/private-data/catalog/`를 사용한다.
- 정보나루 `srchDtlList`의 `description`도 최대 500자의 일반 텍스트 발췌로 보관한다. 도서관 제공 소개이며 사용자가 쓴 독서 메모나 전체 본문 요약과 구별한다. 분류번호가 없거나 올바른 KDC 형식이 아니면 분류 확인 완료로 표시하지 않는다.
- 논문·간행물 PDF 및 범위 확인 대기 PDF는 상세 수집에서 제외한다. 일반 도서 PDF는 `processing_scope=full`로 확인된 자료만 대상으로 한다.
- PDF 쪽수는 로컬 색인 결과로 채운다. 학술지 파일명에 저자·논문제목·발행처가 명시되어 있으면 구조화하고 원본 파일명은 보존한다.
- `scripts/pdf_thumbnails.py --index <색인 경로>`: 인터넷 표지가 없는 자료의 원문 첫 페이지를 작은 미리보기로 만든다. 표지와 다를 수 있음을 상세 화면에 표시한다.
- 원본 파일과 독서 기록, 사용자가 작성한 책 정보는 보존한다. 검증된 PDF 식별 작업만 빈 ISBN·저자·출판사를 이력과 함께 보완한다. 제공자 소개와 표지는 별도 보관하며, 원본 버전이 바뀐 수집 결과는 자동 표시에서 제외한다.
- 과거 `enrich-catalog.ts --online`의 Open Library 일괄 조회는 중단했다. 아래 과거 실적은 당시 결과이며 현재 실행 방법이 아니다.

## 표지 수집과 표시

- 서지 조회 결과의 표지 URL도 함께 저장한다. 정보나루 설명서 v20260620 51쪽의 조건에 따라 해당 이미지는 비영리 화면에 외부 주소로 표시하며, 복사·저장·재배포·AI 입력·학습 대상으로 사용하지 않는다. 다른 제공자의 이미지 보관은 각 제공 조건을 별도로 확인한다.
- 표시 순서는 직접 지정한 표지 → iReadItNow에서 가져온 표지 → 같은 ISBN의 수집 표지 → PDF 첫 페이지 미리보기 → 제목·저자 표시다. 이미지 로딩 실패 시 다음 후보로 넘어간다.
- 정보나루가 `http://image.aladin.co.kr` 표지를 반환하는 경우 같은 경로의 HTTPS 제공을 실제 표본으로 확인하여 HTTPS 주소로 보관한다. 임의의 다른 HTTP 호스트·추가 포트·인증정보가 든 주소는 이 변환 대상이 아니다.
- 수집 표지는 별도 `catalogCoverUrl`로 전달한다. 사용자의 기존 표지 필드와 원본 이미지를 바꾸지 않는다. 현재 소유자·원자료 버전·ISBN·제공자 근거·숨김/되돌림 상태를 확인한 결과만 표시한다.
- 추가 도서 정보에서 보강 서지를 숨기면 그 표지도 즉시 표시 대상에서 빠진다. 출처와 수집일은 펼쳐 보는 근거 정보에 남긴다.
- ISBN이 없거나 판본을 확인할 수 없는 책은 제목이 비슷하다는 이유만으로 다른 판본의 표지를 붙이지 않는다. 별도 확인이 필요하다.

## PDF의 ISBN 및 제목 조사

2026-10-15 우선 수집: 전체 본문 OCR을 기다리지 않는다. `--ready-only --isbn-only`로 앞뒤 페이지가 준비되고 ISBN 후보가 있는 책을 먼저 조회하고, 이어 `--ready-only`로 제목·저자 검색을 보완한다. 의미 있는 저자가 있으면 정보나루 `srchBooks`의 `title`·`author` AND 검색을 먼저 사용하고, 결과가 없으면 제목만 검색한다. 파일명의 저자·제목 순서가 불확실하면 양쪽 방향을 검색 힌트로만 사용한다. 이 동작은 사용자 제공 API 설명서 v20260620 49–50쪽의 검색 조건을 따른다.

수집 감독 작업은 한 번에 100권씩 진행하고 새 앞뒤 OCR 결과가 생기면 재개한다. 각 책의 결과·검색 응답을 저장하므로 동일 근거를 다시 조회하지 않는다. 이전 제목 단독 검색 캐시도 재사용한다. 앞뒤 페이지가 모두 처리돼도 OCR 번호나 제목 검색만으로 찾은 결과는 검토 후보이며, 원문 ISBN·정확한 판본 조건을 통과한 책만 자동 반영한다. 조회에는 ISBN·제목·저자만 전송하고 개인 기록·PDF 본문은 전송하지 않는다.

`node --env-file=.env.local --import tsx scripts/identify-pdfs.ts`는 기존 색인의 앞 12쪽·뒤 8쪽만 읽어 후보를 조사한다. `--online`은 동일 ISBN과 제목 후보를 도서관에서 조회하고, `--apply`를 함께 지정하면 검증된 빈 서지 필드를 보완한다. `--limit`은 이번에 조사할 자료 수이며 1~5,000개다. 실사용 중 자동으로 실행되는 작업은 아니다.

앞뒤 페이지가 빠졌거나 OCR이 남아 있으면 자동 보완하지 않는다. 숫자 검산, 원래 문자층의 명시적 ISBN, 모호하지 않은 단일 ISBN, 권차·판 표시를 유지한 정확한 제목, 저자·출판사 충돌 없음, 파일·도서 버전 일치를 확인한다. 제목 검색용으로 줄인 표현을 자동 판본 확인에 사용하지 않는다. OCR만 있는 번호·복수 ISBN·제목만 찾은 결과는 검토 자료다.

ISBN·저자·출판사 보완, 수정 이력, 제공자 보강 자료는 하나의 트랜잭션으로 저장한다. 중간 저장이 실패하면 전체 반영이 취소되어 다음 실행에서 다시 처리된다. 메모와 독서 이력은 바꾸지 않는다. 책 상세의 ‘PDF 판본 확인 근거’에서 번호가 나온 쪽으로 이동할 수 있다.

결과·진행 상태는 `CATALOG_CACHE_DIR/pdf-identity/`, 제목 검색 캐시는 `title-search/`에 저장한다. API 오류나 한도에서 멈추고 같은 명령을 재실행하면 변경 없는 결과와 캐시를 재사용한다. OCR이 진행돼 앞뒤 페이지의 근거가 달라지면 다시 판단한다. 현재 검토 후보 전체를 편집하는 전용 화면은 후속 작업이다.

2026-10-14 21:50 첫 오프라인 조사: ISBN이 비어 있던 일반 도서 PDF 4,042개 중 오류 상태 7개를 제외한 4,035개를 조사했고, 1,651개에서 ISBN 후보를 발견했다. 2,012개는 앞뒤 OCR 대기가 있었다. 이는 조회·판본 확정 건수가 아니다. 실제 표본 5권 중 2권은 보완을 유지하고, 2권은 강화된 앞뒤 OCR 기준에 따라 반영을 되돌려 재검토, 개정판 제목이 다른 1권도 검토 대상으로 남겼다. 기존 메모·독서 이력의 행 지문은 그대로였다.

전체 설계 근거와 다음 단계는 [연구 기반 개념 정리](knowledge-library-concept.md)를 따른다.

## 인증키: 사용자가 할 일

1. [도서관 정보나루 Open API 안내](https://data4library.kr/apiUtilization)를 열고 회원가입·로그인을 한다.
2. 이용신청에서 인증키를 신청한다. 활용 목적 예시: `개인 소장 종이책·전자책의 ISBN 기반 서지정보, 분류번호, 표지 및 책소개 조회. 비공개 개인 지식서재 구축과 독서 자료 관리에 활용.`
3. 발급된 키를 PC의 `C:/Users/admin/Documents/일상 작업/지식서재 인증키.env` 파일에 있는 `DATA4LIBRARY_KEY`의 따옴표 안에 넣고 저장한다. 채팅에는 키 대신 저장 완료만 알린다.

```dotenv
DATA4LIBRARY_KEY="발급받은 인증키"
```

회원가입의 비밀번호 설정·본인 확인·약관 동의는 사용자가 직접 진행한다. 파일은 Git 저장소 밖에 준비하며 기존 키 파일은 덮어쓰지 않는다.

## 인증키: 개발자가 할 일

1. 저장 완료 후 키를 출력하지 않고 필요한 항목만 앱의 `.env.local`에 연결한다. 기존 DB·로그인 설정을 보존하며 `NEXT_PUBLIC_` 접두사를 사용하지 않는다.
2. 소량의 실제 ISBN으로 인증 성공과 응답을 확인한다. 인증 오류와 검색 결과 없음은 구분하고, 오류 응답을 정상적인 빈 결과로 저장하지 않는다.
3. 같은 ISBN의 표지·서지를 5권 먼저 검토한 뒤 범위를 확대한다. 사용자 기록은 보존하고 제공자 정보를 별도로 저장한다. 한도 또는 오류가 생기면 멈추고 재개 지점을 남긴다.
4. ISBN 미확인·표지 없음·조회 실패 항목은 따로 확인한다. 정보나루에 없는 자료는 Google Books 등 사용 조건이 맞는 보완 경로를 검토한다.

## 재실행해도 유지되는 호출 한도

두 정보나루 조회 경로와 Google Books 조회는 요청 전에 `private-data/catalog/api-usage.sqlite`에 사용량을 기록한다. 기본값은 제공처별 최근 24시간 450회다. 승인 거절·네트워크 실패도 이미 시도한 호출로 포함하며 캐시 읽기는 포함하지 않는다. 프로세스가 동시에 실행되어도 동일 파일의 트랜잭션으로 한도를 공유한다. 키 자체는 저장하지 않는다.

현재 PC의 공통 호출 기록은 `CATALOG_API_USAGE_PATH=E:/지식서재 작업/private-data/catalog/api-usage.sqlite`다. 앱 조회와 수집기가 이 파일을 함께 사용한다. 캐시 위치와 호출 기록 위치를 바꾸더라도 이미 사용한 호출 기록을 초기화하지 않는다.

`DATA4LIBRARY_DAILY_LIMIT`로 조정할 수 있다. 500회 이상은 실제 서버 IP 등록 후 `DATA4LIBRARY_IP_REGISTERED=true`를 명시해야 한다. [정보나루 공식 공지](https://www.data4library.kr/noticeV?cn=194)에 따르면 2023-11-20부터 서버 IP 등록 시 하루 30,000회까지 허용한다. 기본값 450회와 최근 24시간 계산은 앱의 자체 보호 설정이며 공식 제한 또는 공식 초기화 시각을 뜻하지 않는다. Google은 `GOOGLE_BOOKS_DAILY_LIMIT`을 사용한다. 여러 PC나 다른 프로그램에서 같은 키를 쓰면 그 호출량까지 이 로컬 파일이 알 수 없으므로 수집기를 한 PC로 통일하고 제공처의 제한 응답에서도 중단한다.

2026-10-14 IP 등록 확인 정정: 사용자가 제공한 승인 완료 화면에서 서버 IP 등록을 확인했으며, 현재 수집 PC의 공인 IP와도 일치했다. 로컬 비공개 설정을 `DATA4LIBRARY_IP_REGISTERED=true`, `DATA4LIBRARY_DAILY_LIMIT=30000`으로 변경했다. 기존 호출 기록은 보존하고 최근 24시간 합산 방식은 유지한다. 실행 중인 배치는 시작 시 설정을 유지하며 다음 배치부터 변경값을 읽는다. 서지 수집을 순차 실행하고 요청 사이 1.1초 대기는 유지한다. 기존 450회 설정은 등록 상태를 반영하지 못했던 앱 설정이었다. IP가 변경되거나 다른 서버에서 수집할 때는 다시 등록 상태를 확인한다.

한도나 오류로 중단해도 제공처별 `status.json`과 정상 수집 캐시는 남는다. `--limit`은 실제 새 요청 수와 반영 대상 수를 각각 제한한다. 같은 명령을 다시 실행하면 캐시부터 재사용한다. 한도 초과는 재개 가능 시각을 표시하며 자동으로 새 프로세스를 예약하지 않는다. 새 날짜가 되더라도 최근 24시간을 넘기기 전에는 보수적으로 대기한다.
