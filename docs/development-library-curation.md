# 개발 중 자료 정비

앱 시작과 분리된 도구다. 원문·개인 메모·독서 이력을 자동 수정하지 않는다. 논문·간행물·범위 확인 대기 PDF는 목록의 기본정보만 보관한다. 강해집과 성경 주석서는 일반 도서에 포함한다.

## 안전한 순서

1. 소유자별 온라인 DB 백업과 로컬 색인 백업을 원본과 별도로 만든다.
2. `node --env-file=.env.local --import tsx scripts/curate-library.ts inventory --run <이름>`으로 현황을 조사한다. 원본 PDF 폴더는 `E:/전자도서관`이다. `private-data/curation/<이름>/inventory.json`에 버전·누락·범위·스냅샷 해시와 원문이 보관된다. 이미 있는 조사는 덮어쓰지 않는다.
3. 같은 명령의 동작을 `sample`로 바꾼다. 서지 30건, 기록 20건, 모호 사례 10건을 중복 없이 고른다. 자료가 부족하면 실제 수만 보고한다. 같은 파일 해시도 자동 병합하지 않는다.
4. 그 폴더에 T2 CurationItem 배열 `items.json`을 준비한다. 제목/태그만 읽었으면 coverage=metadata다. 인용은 원문과 정확히 일치해야 한다. 작성 경위 codex/rule/provider/api는 보존한다. 날짜나 사용자 주장을 추정해 확정하지 않는다.
5. `validate`, `apply`는 기본적으로 변경하지 않는다. 검증 결과를 확인한 뒤 `apply --apply`로 최대 100건을 보조 정보에 반영한다. 반영 시 현재 원문 버전을 다시 검증한다. `rollback --apply`는 이후 사람이 수정한 항목을 보존하고, `seal --apply`는 실행을 종료한다.

개인 파일은 Git에 포함하지 않는다. 검증 결과의 '유효'는 인용·버전 등 기계적 조건의 통과이며, 사람의 유용성 검수와 다르다. 표본의 90% 이상이 유용하다는 사용자 검수 전에는 대량 AI 태그 적용을 확대하지 않는다.

## 서지 수집

`scripts/collect-catalog.ts`는 ISBN이 정확히 일치하는 도서관 정보나루 결과를 수집한다. `--google`은 Google Books다. 기본 실행은 저장된 응답만 조사하며, `--online`에만 네트워크를 사용한다. `--apply`에만 출처와 보조 서지를 DB에 보관한다. `--limit 30`으로 한 실행의 조회/반영을 제한하며 100권을 넘기지 않는다. 응답 캐시를 재사용하고 완료 항목은 재시작 때 건너뛴다. 429 등 오류에서 중단하며 자동 우회하지 않는다.

인증키는 각각 `DATA4LIBRARY_KEY`, `GOOGLE_BOOKS_API_KEY`로 PC에만 둔다. 조회는 ISBN 등 공개 서지 정보만 전송하며 개인 메모는 전송하지 않는다. 제공자가 반환하지 않은 목차·소개·리뷰를 만들어 채우지 않는다. Google 소개 발췌는 제공자 설명으로 표시하며 AI가 책 본문을 읽은 요약으로 표시하지 않는다. 공식 KDC는 도서관의 실제 번호가 있는 경우만 확인 상태다. 제목만 비슷하거나 다른 번역판인 결과는 확정하지 않는다.

현재 원본 서지 필드를 덮어쓰지 않고, 확인된 보강 정보를 별도 보관한다. 사용자가 필요할 때 검토·수정할 수 있으며 기존 필드와 충돌할 때 원래 값이 우선한다. 원본 수정과 보조 정비의 되돌리기 경계를 지키기 위한 선택이다.

키 미설정, ISBN 없음, 미일치, 원문 미추출, 사람 검수 대기는 각각 남은 작업이다. API 어댑터 구현을 전체 도서의 정보 수집 완료로 세지 않는다. 온라인 키가 없는 동안에도 로컬 색인/OCR·목록 조사·개인 기록 검증은 진행할 수 있다.

공식 안내: [Google Books API](https://developers.google.com/books/docs/v1/using), [도서관 정보나루](https://www.data4library.kr/apiUtilization). Open Library의 실시간 API는 대규모 수집용으로 사용하지 않는다. Aladin은 서비스 종료 공지가 있어 새 기본 의존성으로 채택하지 않았다.

## PDF 처리와 복구

`scripts/pdf_library.py`는 기본 추출을, `scripts/pdf_ocr.py`는 빈 페이지의 OCR을 재개한다. [OCR 안내](pdf-ocr.md)를 따른다. 원본이 바뀌면 결과 반영을 거절하며 목록 재조사로 갱신한다. 완료된 페이지를 재시작 때문에 다시 호출하지 않는다. 로컬 색인은 온라인 웹앱의 목록과 별개로 PC에 남는다.

작업 실패 시 완료된 보조 항목/캐시를 지우지 말고 원인을 고친 후 같은 실행을 재개한다. 잘못된 보조 정비는 해당 run의 rollback으로 되돌린다. PDF 원본 복원은 필요 없다. 생성된 색인을 백업에서 복구해야 할 경우 작업기를 중지한 상태에서 별도 복사본으로 확인한다.

## 2026-10-14 표본 적용 결과

60개 표본의 보조 태그를 실제 DB에 반영하고 실행을 종료했다. 개인 원문과 날짜·독서 기록 해시는 동일하다. 유용성은 60건 모두 사람 검수 대기이며 대량 적용으로 확대하지 않았다. 검색 질문 20개와 비교 30쌍도 같은 비공개 실행 폴더에 저장했다. `scripts/evaluate-library-assist.ts <실행이름>`으로 미판정·보류·비용·무변경·확대 조건을 계산한다. 보고서는 앱을 자동 활성화하지 않는다. 상세한 현재 범위는 [검수 결과](human-owned-library-acceptance.md)를 따른다.
