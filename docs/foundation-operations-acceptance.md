# 승인 대기 중 기본 기능 검수 기록

2026-10-14. 실행 계획: [자료 보존·조회 개선](superpowers/plans/2026-10-14-library-foundation-operations.md). 이번 범위는 서지 API 호출량 관리, 복원 가능한 백업, 대용량 도서 목록 조회다.

## 구현 결과

- 서지 제공처별 최근 24시간 호출량을 로컬 SQLite에 저장한다. 기본 450회, 실패 포함, 캐시 제외, 동시 프로세스와 재실행에서 공유한다. 한도·오류로 중단돼도 정상 캐시와 진행 상태가 남는다.
- 화면 아래 ‘백업과 복원’을 추가했다. 21개 지식 테이블을 무결성 검사용 해시와 함께 내려받고, 검사를 거쳐 빈 서재에만 전부 복원한다. 원자료와 수정 이력은 보존하고 인증·기기 토큰·자동 작업은 제외한다.
- 도서 목록은 24권씩 서버에서 조회하며 검색·분야·책장·독서 상태·형태·정렬을 지원한다. 상세 원자료는 책을 열 때 읽는다. 메모·사유 연결의 책 선택, 주제별 자료 찾기도 전체 목록에서 검색한다.

## 실제 자료 검수

복원용 백업 85,225,200바이트를 별도 PGlite에서 복원했다. 도서 10,994건, 메모 157건, 독서 이력 419건, 수정 이력 47,273건 등 21개 테이블의 전후 차이는 0건이다. 개인 백업과 상세 집계는 `private-data/backups/2026-10-14/`에 있으며 Git에 포함하지 않는다.

처음 받는 데이터는 13,319,388바이트에서 569,326바이트로 약 95.7% 감소했다. 달력·메모에 필요한 책 참조 누락 0건, 첫 두 페이지 중복 0건이다. 전체 내보내기와 백업은 페이지 제한을 적용하지 않는다.

## 자동 검증

최종 수정 후 단위·통합 테스트 137개(45개 파일), 브라우저 테스트 37개, TypeScript 검사와 프로덕션 빌드가 통과했다. 브라우저 검사에는 작은 화면, 지연된 검색 응답, 부분 목록 밖의 책 편집·메모 연결·주제 조회, 복원 전 검사·기존 서재 보호, 비로그인 접근 차단이 포함된다.

별도 검토자가 세 작업 전체를 검토했다. 복원 JSON의 내부 구조 검사 누락은 중요한 문제로 확인했고, 주제 검색의 이중 필터는 실제 태그·ISBN 검색 결과를 숨길 수 있어 중요한 문제로 재분류했다. 두 문제 모두 재현 테스트 실패를 확인한 뒤 수정했고 전체 테스트를 다시 통과했다. 보류한 경미한 지적은 없다.

복원 검증은 체크섬을 다시 계산한 18종의 손상된 내부 구조도 검사·저장 양쪽에서 거부하며, 대상 서재가 빈 상태로 남는지 확인한다. 연구 자료와 생각 변화가 있는 정상 백업도 복원 후 읽힌다. 실제 85,225,200바이트 백업 역시 강화된 검증으로 다시 복원해 전후 차이 0건과 사유의 지도 조회 성공을 확인했다. 재검수는 저장된 백업과 별도 메모리 DB만 사용했다.

## 구현 중 판단과 한계

복원 요청의 기본 한도를 실제 약 81 MiB 자료에 맞춰 128 MiB로 늘렸다(파일 선택은 127 MiB). 따라서 복원 중 임시 메모리 사용이 크며, 향후 서버리스 배포에서 대용량 업로드는 별도 구현이 필요하다. 현재 대용량 복원은 로컬 앱에서 수행한다.

시간대가 다른 DB 사이에서도 동일한 자료로 검증되도록 시각은 UTC로 직렬화한다. 날짜만 있는 독서일과 시각의 소수점 정밀도는 유지한다. PDF 원본·색인·가져온 표지 파일은 별도 백업 대상이다. 메모·독서 이력 자체의 페이지 조회와 파일 경로 재연결 화면은 후속 작업이다.

검토에서 유지한 판단은 다음과 같다.

1. 호출량 한도는 같은 PC의 동일 SQLite 경로를 쓰는 수집기끼리 공유한다. 다른 PC·클라우드와 동시 수집하려면 공통 한도를 별도로 구현해야 하며, 그렇지 않으면 합산 호출량이 초과될 수 있다.
2. 페이지 조회의 제목·저자 정렬은 안정적인 문자 코드 순서다. 혼합 언어와 기호의 순서는 사전식 정렬과 다를 수 있다.
3. PDF 조각의 실제 존재는 별도 색인으로 사용 시 확인한다. 파일 경로는 설정된 루트 안으로 제한하지만, 온라인 기록만 복원해서는 누락된 PDF·색인을 복구할 수 없다.
4. 원본·수정 이력 안의 과거 식별자는 그대로 보존한다. 접근 권한은 현재 소유자 열로 판단하며, 향후 기능도 역사적 식별자를 인증 수단으로 사용해서는 안 된다.
5. 서버리스 대용량 업로드와 외부 PDF 실행 도구의 설치 여부는 별도 운영 조건이다. 다른 호스트에서 사용하려면 업로드 경로·실행 환경을 먼저 확인해야 한다.
6. 검토자는 제공처 승인·실제 네트워크와 빌드를 재실행하지 않았다. 빌드는 구현자가 통과를 확인했고, 실제 API 품질·승인은 승인 후 5권 시험으로 검수한다. 모의 응답 테스트가 실제 제공처의 동작을 보장하지는 않는다.

이번 작업은 온라인 DB 읽기와 별도 로컬 시험 공간을 사용했다. 온라인 DB 쓰기·실제 서지 API 조회·AI API 호출·GitHub push·배포는 하지 않았다. 기존 OCR 작업기는 그대로 실행 중이다. 승인 후에는 5권의 실제 서지·표지 조회를 먼저 검수한다.
