## 적용 내용

1. **정확한 모델 출처**: 사용자가 AI 태그·주제를 채택할 때 `generator`에 상수 `gpt-6-luna` 대신 확인한 응답의 `provenance.model`과 `provenance.promptVersion`을 기록한다. 생각 비교 후보의 `provenance`에도 검증된 실제 모델·프롬프트·스키마 버전을 사용한다. 이전 저장 데이터는 자동 재기록하지 않는다.
2. **작업별 Sol 출력 예약**: GPT-6.1 Sol에서 태그/기록 정리·발췌 설명 최대 출력 상한 8,192→4,096, 두 기록 비교 8,192→6,144, 종합 연결 분석 8,192 유지. Luna 일반 요청 2,000 및 종합 분석 8,192 유지. 이 숫자는 실제 청구 토큰이 아니라 추론 토큰을 포함한 생성 상한이다. 짧은 요청의 **최악 비용 예약**을 줄이는 효과가 있으며 실측 비용 절감률을 보장하지 않는다. 
3. 테스트: Sol 태그 출처의 저장값과 작업별 요청 한도·예상 상한에 대한 회귀 검사 추가.

## 후속 검증 및 개선 과제
- `npm ci && npm run typecheck && npm test -- --maxWorkers=2 && npm run build` (실행 환경에서 수행)
- 실제 사용자의 모델 권한, 네트워크 응답, 청구 내역 및 Sol의 medium reasoning 출력 완결성은 **아직 미검증**. 가상 자료만으로 회귀 검사 후 필요하면 상한 재조정
- 8,192→4,096 변경은 출력 예약 최대치를 줄이는 것이지 동일 내용 요청의 실청구 비용을 항상 줄이는 것은 아니다. 데이터 기반으로 재평가
- `/v1/responses/input_tokens`를 이용한 입력 토큰 사전 계산은 별도 API 전송과 개인정보·비용·예약 흐름 검토가 필요해 이번에는 도입하지 않는다
- 검색/연결의 임베딩 도입은 별도 품질 기준(Recall@K, 사람 채택률, 실제 API 청구 비용)과 사용자 선택 범위 동의 후 판단
- 실제 iOS·PC 동기화·전체 OCR 색인 검증과 생산 배포는 원래 인수인계 작업의 미확인 항목으로 유지
