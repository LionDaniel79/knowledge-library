# Windows 앱 수집 메뉴 통합

## 구현

- 기존 WPF 앱을 PDF 검색·OCR, PDF 도서정보 수집, 로고스 도서정보 수집으로 분리.
- 종류별 일일 조사 한도 저장(로고스 0~600, PDF 0~500), 기본 300/100. 일시정지, 수동 요청, 배치/도서별 집계 표시.
- HTTP 서버 없이 트레이 앱이 기존 유한 수집기를 순차 실행. 한국시간 09:00/21:00 Logos, 15:00 PDF. 로그인 자동 실행은 `--tray` 지원.
- 기존 체크포인트·API 원장·일일 예약/조사 ledger와 전역 중단을 그대로 사용. 배치 최대 100권, PDF 기존 API 160회/선택 OCR 20쪽 제한 유지.
- 날짜 변경 후 수동 요청 재실행 방지, 프로세스 간 잠금 및 잠금 복구 직렬화.
- 기존 실행 소스의 미커밋 수정에는 진행 통계 훅만 추가하고 원본을 비공개 운영 폴더에 보존.

## 로컬 운영 반영

설치 전 현재 OCR 쪽 완료 후 일시정지·대기 상태를 확인했다. 기존 실행 앱이 작업하지 않는 상태에서 교체하고 OCR을 재개했다. 원본 PDF/기존 색인은 교체하지 않았다. 새 버전별 실행 폴더, 기존 상태·연결 설정을 재사용한다. 로그인 시작프로그램은 새 실행기를 트레이로 시작한다.

기존 Logos/PDF 예약 작업 XML과 연결·설치 설정을 비공개 운영 폴더에 보존한 뒤 두 예약 작업을 비활성화했다. 새 트레이 호스트의 실행 heartbeat와 기존 전역 중단 보존을 확인했다. 웹 배포는 필요하지 않아 수행하지 않았다.

## 검증

- Node 관련 시험 9개: 한도/부분 배치 예약, 낮춘 한도, 일시정지, 날짜/수동 요청 재실행 방지, 기존 중단 보존, 동시 잠금 복구, 기존 배치 검산 통과.
- 관련 TypeScript 단위시험 17개 및 `tsc --noEmit` 통과.
- WPF 일반 빌드·수집 화면 격리 스모크 통과(3메뉴, 설정 저장·재조회, 일시정지, 오류 표시).
- 기존 격리 WPF 검색/OCR/쪽 열기/검색 취소/등록/감지/트레이/종료 스모크 통과.
- 실제 프로필·설치 경로의 미리 점검 `--check` PDF/Logos 통과. 외부 API/DB 쓰기는 실행하지 않음.
- 실제 새 앱 접근성 정보에서 세 메뉴 존재 확인. 실제 선택 클릭 검수는 창 활성화 도구 오류로 미완료이며 격리 스모크로 대신 검증.
- 코드 검토에서 발견한 수동 요청의 다음날 재실행과 오래된 잠금 복구 경쟁을 수정하고 회귀시험 추가.

## 미해결

전환 전부터 존재한 `TypeError` 전역 중단의 정확한 원인은 미확정이다. 이 중단을 자동 해제하지 않았다. 저장된 후보의 읽기 전용 비교로 오류를 재현하지 못했다. 따라서 이번 작업의 **화면/트레이 통합은 완료되었으나 실제 서지 수집 재개와 외부 API를 통한 새 자동 적용은 미검증/미실행**이다. OCR은 별개로 계속한다. 사용자의 중단 해제나 반복 클릭을 요구하지 않는다.

기존 작업으로 되돌릴 경우 새 앱을 종료한 뒤 보존된 연결 설정·바로가기·예약 작업 XML을 사용한다. 새 실행기와 옛 예약을 동시에 활성화하지 않는다. `.recovery` 파일은 실제 프로세스가 없는지 확인한 경우에만 운영자가 보관 후 정리한다.
