# AI owned-book recommendations

Home replaces only its calendar panel with `AI가 추천하는 나의 책`. The calendar menu and reading statistics remain. Paper/PDF/Logos tabs each show one carousel card at a time (up to3 recommendations), with touch/mouse/arrows/keyboard and existing book details.

Only an explicit first-generation or refresh click calls the provider. Mount/tab navigation reads persisted results without paid generation. Server and owner-scoped device cache retain the last successful result through navigation/reopening and failures; canonical results can still hydrate a new device after a failed newer attempt. Server filtering removes books newly read, excluded or deleted. Empty authoritative results clear stale cache, while unconfirmed empty failures retain it.

The server randomly samples unread active owned books, preferring candidates absent from the previous request. It uses bounded pools and matching so multi-format holdings do not starve another format; each book ID is sent once, at most50 per format/150 total. Recommendation IDs must match supplied candidates and format, be globally unique, and fill exactly min(3, available) per format. Eligibility is rechecked before publication. No external books are recommended.

Taste metadata combines currently reading books with completed/started books from the inclusive Seoul calendar interval today minus29 days through today, deduplicating book IDs while keeping distinct statuses. Data is limited to ID/title/author/category and bounded existing publisher/ISBN/tags. Notes, source_data, PDF text, covers and private paths are never sent to the provider. Excessive input size is blocked rather than silently truncating required reading history.

The model is fixed to `gpt-6-luna` and has no model-selection UI. A dedicated Responses JSON schema adapter shares existing rates/configuration and cost calculation; existing note-assistance purposes remain unchanged. The request reserves the conservative UTF-8 input/output estimate through the existing per-request/monthly budget ledger, marks sending durably before the provider and settles known usage even for invalid/incomplete output. No caps are raised. Uncertain sends retain the maximum reservation and are never automatically reissued. Same request IDs replay safely; owner leases/unique index prevent concurrent generation. Failed refreshes do not replace the last successful result. Reasons are explicitly based on metadata rather than verified full-text reading.

Migration042 is additive and rerunnable, with minimal SELECT/INSERT/UPDATE runtime grants on two server-owned tables. Candidate IDs/leases are excluded from full replica synchronization; authenticated bounded GET returns at most9 hydrated books. Existing backups/data/sync contracts are unchanged. Real production schema application verified19 existing tables (including books, personal records and AI policy/usage) had identical counts/content fingerprints; new tables remained empty. Original PDF/OCR/SQLite and private settings were untouched.

Validation:835 unit tests passed,4 existing conditional skips;16 focused browser tests passed. Typecheck, production build and formatting passed. Tests include mixed-format quotas, stale/foreign/noncandidate IDs, shared budgets, replay/lease uncertainty,30-day boundaries, changed eligibility, offline/cache recovery and home-only calendar replacement. Independent review identified mixed-format starvation and failed-request cache hydration; both were corrected and regression-tested.

No live paid OpenAI call was made. Provider tests use synthetic responses and metadata only. Real provider/model availability, live recommendation quality and physical phone/tablet interaction were not independently exercised. Remote GitHub CI remains subject to the existing account allowance.
