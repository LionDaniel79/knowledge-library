# PDF 열람과 읽은 쪽 저장 수정 — 2026-10-17

책 상세창의 두 링크는 같은 PDF 문서·페이지를 가리켰다. ‘PDF 원문 열기’ 하나를 남겼다. PC의 3001 포트에 실행 중인 서재가 없었고 이전 실행 기록의 PID는 다른 프로그램이 재사용하고 있었다. 해당 PID를 종료하지 않고, 기존 비공개 서버를 복구했다. 서버는 Windows의 본인 계정 작업으로 실행하며 기존 시작프로그램 바로가기가 그 작업을 시작한다. 외부 공개나 관리자 권한 추가는 없다.

PC 주소에 처음 접속하거나 로그인이 필요한 경우에는 해당 PDF의 UUID·페이지·인용 서명으로 로그인 후 돌아온다. 임의 외부 주소·추가 이동 매개변수·범위 밖 페이지는 허용하지 않는다. 원문 읽기 전 소유자 검증도 유지한다.

읽은 쪽 저장은 기기의 기존 송신 대기열에 먼저 기록하고 폼을 닫는다. 최초 전체 다운로드 중에도 현재 표시된 책·독서 상태를 기준으로 진행 기록만 보관할 수 있다. 다운로드 완료 전에는 전체 기기 저장을 완료로 표시하지 않는다. 재열기 시 대기 기록을 온라인 목록 위에 반영하며 서버는 기존 버전·요청 번호·계정 검증을 거친다. 저장 실패 시 창을 닫고 성공으로 표시하지 않는다.

전체 목록을 다시 받는 작업은 진행 저장의 응답 경로에서 제외했다. 새 독서 쪽수와 버전을 제자리에서 갱신하고, 읽는 책은 생성일·ID 순서로 유지한다. 기존 기록을 갱신하며 배열 끝에 다시 붙이던 동작도 수정했다.

## 별도 검토 판정

독립 검토 1회의 중요 지적 2개를 모두 재현하고 수정했다. 재검토를 요청하지 않았다.

- P1 계정 전환과 지연된 화면 읽기: 대기열을 읽은 뒤 현재 runtime·취소 여부를 다시 확인한다. 정상 조회와 재시도 경로 모두 이전 계정 화면이 되살아나는 실패를 재현한 뒤 통과를 확인했다.
- P2 최초 복사 승격과 저장의 겹침: 송신 대기 저장과 활성 checkpoint의 수정 번호 갱신을 같은 저장소 거래에서 수행한다. 원시 자료는 35쪽인데 화면은 20쪽이었던 실패를 재현하고 화면까지 35쪽으로 유지됨을 확인했다.

검토자가 별도 문제로 분류하지 않은 로그인 복귀·송신 확인과 충돌·로컬 충돌 입력 보존·목록 순서도 기존 요구에 맞게 유지했다. PDF 원본과 개인 기록은 검증용으로 수정하지 않았다.

## 검증

최종 단위 검사 426개, 전체 브라우저 검사 85개, 390px WebKit의 관련 검사 5개, 타입·포맷·배포 빌드 통과. 배포 추적 814건에서 비공개 파일 포함 0건. 실제 문제의 『비즈니스 프레젠테이션영어』 PDF는 PC 연결 복구 후 87페이지 문서의 첫 이미지까지 확인했다. 사용자 도서의 진행 쪽수를 임의로 바꾸지는 않았다. 휴대폰의 실제 입력·동작 확인은 사용자 기기에서 진행한다.
