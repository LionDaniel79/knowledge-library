# 전체 기기 저장과 변경분 동기화

온라인 서재의 허용된 38개 업무 테이블을 계정별 IndexedDB에 저장한다. 표지 원본 바이트, 목차, 메모, 과거 이력, 검토 후보, 제외 자료, 연구 자료와 저장된 AI 결과를 포함한다. 외장 PDF·OCR 색인과 계정 인증 비밀정보는 포함하지 않는다. 가져온 원본 JSON 안의 인증 필드와 URL 접근 토큰도 기기 전송에서 제거하며 서버 원본은 보존한다.

## 사용

- 나의 서재에서 ‘책 추가’ 왼쪽의 ‘동기화’를 누른다. 앱을 다시 열거나 온라인으로 돌아왔을 때도 변경을 확인한다.
- 아래쪽 ‘기기 저장·동기화’에서 전체 저장 여부, 받은 자료 수·크기, 남은 자료, 송신 대기, 충돌과 공간을 확인한다. 용량 부족은 공간 확보 후 재개한다.
- 최초 받기와 검증이 끝나기 전에는 기존 온라인 조회를 사용한다. 일부 자료만 받아 놓고 전체 저장 완료로 표시하지 않는다.
- 충돌은 ‘동기화 확인’에서 처음 내용·서버 내용·내 수정 내용을 비교한다. 선택 전의 내 글과 이전 충돌 원본은 보관한다.
- ‘전체 다시 받기’는 기존 확정 사본과 미전송 입력을 유지한다. ‘내려받은 자료 지우기’는 미전송 입력이 하나라도 있으면 차단하고, 온라인 원본·과거 충돌 기록은 지우지 않는다. 다음 수동 동기화까지 자동 전체 받기를 멈춘다.
- ‘백업과 복원 → 기기 전체 자료 내려받기’는 38개 표와 송신 대기·충돌 원본을 포함한다. 큰 정수·소수·직렬화된 원문을 다시 파싱하지 않고 내보낸다. 이 파일은 검토·보관용이며 기존 복원용 백업과 구분한다.
- iPhone에서는 홈 화면 웹앱과 Safari 탭의 저장소가 다를 수 있다. 실제 사용할 화면에서 최초 받기를 끝내고 오프라인 재열기를 확인한다. 브라우저 사이트 자료를 직접 지우기 전에 미전송 입력을 해결하거나 내보낸다.

## 구조와 제한

소유자별 DB 잠금으로 업무 변경과 순번을 같은 거래에서 확정한다. 순번은 문자열로 전달한다. 자료와 이력은 수정 없이 허용 필드만 투영하고, UTC 시간과 같은 비밀정보 제거 규칙으로 해시를 만든다. 512KiB 이하 응답, 192KiB 조각, 동시 조각 2개로 전체를 분할 전송한다. 조각·원문·테이블별 키/해시를 모두 검증한 새 세대만 활성화한다.

앱은 저장된 자료로 조회하고 별도 송신 대기 원본을 겹쳐 표시한다. 요청 UUID를 재사용하여 응답을 잃어도 중복 반영하지 않는다. 편집창을 연 시점의 필드 기준값을 보존하므로 수집기가 업무 버전을 올리지 않고 서지를 보완해도 충돌을 감지한다. 종속 입력은 선행 입력의 확정 뒤에 보내며, 연구 자료는 선택한 글과 서지를 다시 검사한다. 중복 생성이 반환한 실제 ID는 대기 입력의 구조화된 ID 필드에만 연결한다. 여러 창은 Web Locks와 만료 가능한 저장소 임대·세대 검사를 함께 사용한다. 새 앱 코드는 기존 창이 닫힐 때까지 대기하며 입력 중 강제로 새로고침하지 않는다.

브라우저가 저장소를 제공하지 않으면 인증된 온라인 조회를 유지하고 전체 기기 저장을 주장하지 않는다. 영속 보관 허용과 실제 한도는 브라우저가 결정한다. 전체 자료 모드에서는 표지·과거 이력을 자동으로 버리지 않는다. 재구성 중에는 기존/새 세대가 공존하므로 원본 크기보다 넉넉한 여유 공간이 필요하다. 검증 후 현재 사본과 직전 사본 하나만 보관하고, 더 오래된 중복 세대와 참조가 없는 값 조각은 회수한다. 송신 대기와 충돌 원본은 회수 대상에서 제외한다. 실제 저장소 사용량은 설정 화면의 브라우저 측정값으로 확인한다.

## 재현 검사

```text
node --import tsx scripts/verify-replica.ts --mode verify-only --source generated --browser chromium
node --import tsx scripts/verify-replica.ts --mode verify-only --source generated --browser webkit
node --import tsx scripts/verify-replica.ts --mode verify-only --source generated --sample catalog --browser webkit
node --env-file=<비공개 설정 파일> --import tsx scripts/verify-replica.ts --mode verify-only --source database
```

생성 자료 검사는 D 드라이브의 별도 시험 프로필만 사용한다. 실제 계정 쿠키나 개인 DB를 시험 자료로 쓰지 않는다. DB 검사는 연결을 읽기 전용으로 열어 수·크기·해시만 출력한다. 기록·도서를 자동 수정하지 않는다.

2026-10-17 생성 자료 기준: Chromium은 160,000행·약 222MiB, 4.5MiB 한 행, 전체 표지의 중단·재개·검증을 통과했다. 준비 후 목록/정렬 응답 p95는 4.5ms였다. WebKit의 6천 권·1천 기록(7,034행·12MiB) 검사에서는 p95 47ms, 첫 색인 1.45초였다. 두 검사 모두 변경 없는 확인 응답은 127바이트이고 자료·이미지 재전송은 0이었다. 이 수치는 생성 자료·시험 PC의 결과이며 실제 iPhone 측정치가 아니다. Windows WebKit의 대량 저장 요청은 느리므로 최초 저장 시간과 실제 iPhone의 최종 저장 완료는 별도 확인한다.

## 운영 전환과 되돌리기

1. 만료되는 DB 사본에서 026 스키마, 순번·동시 쓰기, 전체 테이블의 수·해시, 업무 원본 불변을 확인한다.
2. 운영 원본의 수·해시를 기록한 뒤 추가 스키마 026을 적용한다. 제한 역할에는 추적 표의 조회와 `library_sync_lock(text)`, 순수 투영 함수 `library_sync_redact(jsonb)` 실행만 추가한다. 원본 업무 자료를 갱신하지 않는다.
3. 구버전 수집기/PC 서버를 체크포인트에서 새 쓰기 경계가 있는 코드로 교체한다. 새 불변 PC 배포에 `.next`와 생성된 `public/replica-shell.json`을 함께 복사한다.
4. 공개 웹과 PC 연결을 배포하고 본인 계정의 전체 저장과 다음 변경의 왕복을 확인한다. 원문 PDF 링크는 기존 비공개 PC 연결을 사용한다.
5. 문제 시 온라인 조회로 돌아가되 추적 로그·기기 송신 대기를 버리지 않는다. 새 UI에 미전송 입력이 있으면 먼저 동기화 또는 기기 자료 내보내기를 한다. 복구를 위해 DB를 삭제하거나 세대를 강제로 초기화하지 않는다.

만료된 순번의 기기는 전체를 다시 받는다. 180일 변경 로그 정리는 운영자 작업으로 하며, 원본 수정 이력·제외 상태·삭제 식별자는 보존한다.
