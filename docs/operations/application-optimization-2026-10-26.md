# 전체 코드 점검·정리 및 최적화 — 2026-10-26

## 점검 범위와 기준

변경 전 소스·실행 스크립트 387개와 Next 라우트·프록시·CLI 진입점 111개를 정적 참조 그래프로 조사했다. 동적 import, Web Worker URL과 TypeScript 모듈 해석을 포함하고, 화면·서버·동기화의 주요 경로를 별도로 검토했다. 외부에서 호출하는 API나 운영 유틸리티는 import가 없다는 이유로 삭제하지 않았다.

실제 개인 자료에 테스트 기록을 쓰거나 PDF·OCR 색인·인식 후보·미전송 명령·수정 이력을 지우지 않았다. DB 구조와 기존 동기화 명령 계약을 유지한다. 유료 AI 호출과 서지 수집을 추가 실행하지 않는다.

## 정리한 코드

- 사용 경로가 없는 생산 코드 15개: 삭제된 도서 소개/가져온 기록/구형 PDF 작업 현황/구형 PC 분석 설정 화면, 구형 자동 연결, 구형 생각 흐름 표시 함수, 종료한 로컬 AI 설정·어댑터·분석 작업기와 전용 보조 코드.
- 기존 독립 ‘기록과 생각’ 화면은 이미 ‘사유의 지도 → 내 기록’으로 통합됐지만 LibraryApp의 구형 필터·목록·페이지 계산이 남아 있었다. 접근할 수 없는 화면과 매 렌더마다 메모 본문을 검색하던 계산을 제거했다. 옛 notes 이동은 현재 내 기록으로 계속 연결한다.
- 홈 기록의 태그는 현재 내 기록 화면의 필터로 전달한다. 태그 관리·휴지통·검색에서 공용으로 사용하는 구성 요소는 유지한다.
- 사용하지 않는 import·변수·이전 커서 인코더·로컬 모델 선언을 정리했다. 앞으로 다시 쌓이지 않도록 TypeScript `noUnusedLocals`, `noUnusedParameters` 검사를 활성화했다.
- 종료한 구현만 시험하던 단위 검사 6개 파일과 오래된 화면 전용 검사를 정리했다. 인증·페이지가 고정된 PDF 연결·원문 미요청·기존 큐 호환에 관한 활성 검사는 유지·갱신했다.

## 유지한 잔여 경로

정리 후 참조 그래프에서 남는 두 후보는 의도적으로 유지한다.

- `src/client/replica/memory-storage.ts`: 고립된 기기 저장소 테스트를 위한 메모리 구현이다.
- `src/server/sync/retention.ts`: 운영자가 명시적으로 실행하는 동기화 보존 기간 유지보수 함수다. 이번에 실행하거나 보존 기록을 삭제하지 않는다.

중단된 AI 작업기의 HTTP 410 응답, 기존 큐를 안전하게 거절하는 스크립트, 과거 기록·후보·피드백·백업·MCP 계약과 이력 조회 코드는 호환성과 자료 보존을 위해 유지한다. 현재 AI API 호출, 현재 검색 평가·순위 도구, PDF/OCR·서지 수집 스크립트는 삭제 대상이 아니다. 직접 의존성은 각각 활성 코드나 운영/개발 검사에서 사용하고 있어 임의로 제거하지 않았다.

합성 표본 150권에서 동일한 검색 결과 150권을 유지하면서 주제 연결 방문은 **22,500 → 150**, 독서 기록 ID 방문은 **11,475 → 300**으로 줄었다. 시간 기준이 아닌 실제 반복 작업 수를 비교했다.

같은 의존성으로 만든 esbuild 브라우저 진입 경로 측정에서 조건부 로딩 분리 전후의 즉시 필요한 JS는 **1,309,174 → 1,204,826바이트**, gzip 합계는 **311,058 → 285,937바이트**였다. 이는 모듈 경계 비교이며 실제 iPhone 시작 시간이나 Vercel 전송 절감률을 뜻하지 않는다. 전체 기능을 보관하는 오프라인 셸의 총 코드량은 따로 유지한다.

## 검사와 실제 사용의 범위

기준 검사: 단위·고립 저장소 검사 582개 통과, 4개 건너뜀. 종료한 구현 전용 검사를 정리하고 회귀 검사를 추가한 뒤 전체 검사는 569개 통과, 4개 건너뜀. 검토 중 발견한 같은 커서 보정 경우까지 포함한 추가 런타임·큐·전송·시작 검사는 28개 통과했다.

추가 회귀 검사는 불필요한 테이블 읽기·캐시 재구성, 반복 탐색 예산, 변경 없는/실제 변경/같은 커서 보정/기기 복사본 삭제 알림, MCP 연결 종료, 상태 기록 간격과 즉시 해제, 대량 정렬의 조회 예산, 표지 재검증·다른 소유자 차단을 포함한다.

화면 검사는 실제 개인 DB 대신 가상 응답과 고립 IndexedDB를 사용하는 Chromium/WebKit에서 수행한다. 시작 중 입력 보존, 다른 계정으로의 전송 방지, 기기 복사본 정리·미전송 기록 보존, 검색·태그·도서 수정·메모 상자·OCR 상태·PDF 연결을 확인한다. 개인 iPhone의 실제 기기 간 동기화 검수 전체를 대체하지 않는다. 별도로 사용자가 실제 iPhone에서 OCR 진행률·처리 쪽수 표시를 확인했다.

별도 읽기 전용 코드 검토에서 같은 커서 자료 보정 알림의 누락 가능성을 찾아 회귀 검사 후 보완했다. 삭제했던 복합 검사에서도 활성 PDF 리더 검사는 다시 분리해 보존했다. 최종 화면·빌드·배포 결과는 별도 운영 기록에 남긴다.

최종 검증: Chromium/WebKit 관련 화면 80개와 분리한 PDF 리더 2개, 총 82개 통과. 시작 중 초안 보존, 계정이 바뀌었을 때의 전송 차단, 활성 태그 필터 전달을 포함한다. TypeScript의 새 미사용 코드 검사, 변경 파일 포맷과 운영 빌드를 확인했다. 오프라인 셸·Worker 검사 3개 통과, 배포 추적 파일 18,121개 중 비공개 자료 경로는 0개였다. 실제 개인 자료를 자동으로 수정하는 기기 간 왕복 검사는 실행하지 않았다.
