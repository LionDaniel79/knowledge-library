# 화이트보드 구현·검증 기록

## 후속 수정: 연결선에서 끊기

연결선을 누르면 메모 쌍과 ‘끊기’를 표시한다. 메모 연결은 기존 관계의 상태·버전·되돌리기를 사용하며, 묶음 연결은 해당 두 묶음의 선만 제거한다. 원문 메모·묶음 구성·배치는 유지한다. 접힌 묶음 사이에 여러 메모 관계가 합쳐져도 각 관계를 따로 고른다. 메모 선과 묶음 선이 정확히 겹치면 종류를 선택할 수 있다. 선의 터치 폭과 도구 버튼은 확대와 무관하게 44px를 유지한다.

검사: 순수 모델·격리 저장소 20개, 모의 브라우저 25개, 전체 타입 검사가 통과했다. 수정 전 실패를 확인하고 보완했다. PC 클릭·터치·키보드, 끌어서 이동할 때 오해제 방지, 실패 시 선/선택 유지, 관계별 해제, 되돌리기, 겹친 종류 선택, 저장 중 키보드 조작의 링크 부활 방지를 포함한다. 독립 코드 검토의 중요 지적을 수정하고 후속 검토를 마쳤다. 실제 DB·기기 동기화는 11/1 보류 목록에 추가했다.

E 드라이브(exFAT)의 Node.js readlink가 일반 파일에서 EISDIR를 반환해 로컬 Next 빌드가 중단됐다. 소스를 바꾸어 오류를 숨기지 않고 Vercel의 Linux 빌드로 최종 검증한다. 배포 입력 774개 실제 파일 약 4.7MB를 검사했으며 비공개 자료·환경 파일·PDF·색인·개발 의존성은 포함하지 않았다. PC PDF 서버는 기존 안정 빌드를 유지한다.

## 구현

사유의 지도에 화이트보드를 추가했다. 주제·태그·분야·도서의 검색형 복수 선택과 메모 제목/전체 내용 검색, 포스트잇 이동, 근접 연결, 겹침 묶기, 묶음 접기/펼치기·이동·연결, 주제별 묶음, 원본 메모 열기, 연결 관리와 되돌리기를 구현했다. 메모 연결은 기존 `library_connections`를 사용하고, 묶음 연결은 보드 관계로 보관한다. 기존 관계의 종류와 이유를 덮어쓰지 않는다. 새 AI 호출·유료 서비스·의존성은 없다.

배치와 묶음은 메모 식별자만 참조한다. 전체 메모/책 정보는 로컬 조회 캐시로 재사용하고, 보드 이동만으로 다시 읽지 않는다. 입력은 기기에서 먼저 보관하고, 미전송 배치·버전 충돌·선택 전 추가 편집도 초안에 남긴다.

## 실행한 검증

- TypeScript 전체 검사 통과.
- `tests/whiteboard.test.ts`, `tests/whiteboard-store.test.ts`: 14개 통과. 소유자별 저장·버전·재시도, 실제 메모 연결, 역방향 중복 방지, 기존 관계 보존, 휴지통 제외는 격리 PGlite DB로 검사했다.
- `playwright.whiteboard.config.ts`: 10개 브라우저 검사 통과. 검색, 드래그·묶기·접기·연결·되돌리기, 저장 실패 초안, 모바일 폭·드롭다운, 터치 취소와 해제, 키보드 연결, 같은/낮은 버전의 명시적 배치 선택, 늦은 자기 저장 응답, 이전 해결 전 초안 재진입을 가상 자료로 검사했다. 실제 서버·계정·동기화는 사용하지 않았다.
- Next.js 16.4.2 프로덕션 빌드 및 배포 추적 파일 검사 통과. 개인 자료 경로 포함 0건. 운영 비밀정보 없이 별도 빌드 폴더에서 검사했다.
- 독립 코드 검토에서 미적용 테이블의 백업 호환성, 충돌 해결 후 배치 선택, 되돌리기 버전 조건, 연속 저장 응답과 초안 재진입을 보완했다.

## 11월 1일까지 실행하지 않는 항목

사용자가 동기화 검사를 11월 1일로 지정했으므로 운영 DB 조회·028 마이그레이션 적용·실제 PC/아이폰 변경 왕복·기존 동기화 검사 전체 실행은 보류했다. 기기 초기화·전체 재다운로드·요금제 변경도 하지 않았다. 따라서 위 검증은 운영 동기화 완료를 뜻하지 않는다.

`tests/deferred/whiteboard-sync.test.ts`는 `LIBRARY_RUN_DEFERRED_SYNC=1`을 설정한 11월 1일에 실행한다. 테이블 미적용 상태의 메타·분할 조회·범위/백업 검사·복원, 적용 후 공개 행/명령, 충돌 해결과 보드 읽기의 버전 일치·자료 캐시를 포함한다.

기존 보류 항목과 화이트보드 항목을 `docs/operations/sync-acceptance-2026-11-01.md`로 합쳤다. 2026-11-01 오전 10시(한국시간) 일회 검수 예약 ID는 `11-1`이다. 현재 비공개 PDF 서버의 프로그램 전환도 이 검수에서 웹과 같은 버전인지 확인하고 진행한다.

이번 코드 반영은 기존 전체 동기화 CI를 지금 실행하지 않도록 `[skip ci]`로 기록한다. 일반 검사 영구 제외 설정은 추가하지 않았다.

## 후속 수정: 검색 전 선택 유지

주제·태그를 선택한 뒤 검색하기 전에 배치 자료가 다시 조회되면, 조회된 배치의 필터가 입력 중인 선택을 덮는 현상을 격리 브라우저에서 재현했다. 조회 완료를 기다린 회귀 검사에서 ‘정서’ 선택이 ‘전체’로 바뀌어 실패하는 것을 먼저 확인했다.

검색 조건 편집 여부를 배치 저장 상태와 별도로 관리해, 검색 전의 주제·태그·분야·도서와 검색어를 보호한다. 검색·되돌리기·저장된 배치 사용 같은 명시적 동작에서만 해당 보호를 해제한다.

네 종류의 선택과 검색어를 유지한 뒤 검색하는 회귀 검사, 휴대폰 터치로 복수 선택하고 목록을 다시 열어 체크를 확인하는 검사를 추가했다. 브라우저 검사 12개, 전체 타입 검사와 Next.js 16.4.2 빌드가 통과했다. 실제 DB·동기화 검사는 계속 보류했다.

## 후속 수정: 결과 간격·휴대폰 드롭다운·메뉴 순서

검색 결과가 전체 메모의 원래 위치를 유지해 두 메모가 약 7,124px 떨어지는 현상과, 휴대폰에서 목록을 열자마자 검색칸이 자동 초점을 받는 현상을 격리 브라우저 검사로 먼저 재현했다.

- 검색할 때 일치하는 메모와 묶음을 48px의 카드 간격으로 모은다. 검색되지 않은 메모의 좌표·묶음 소속·연결은 보존한다. 자동 배치였음이 확인되는 기존의 지나치게 성긴 필터 결과도 열 때 보정하며, 직접 이동한 배치는 자동 보정에서 제외한다.
- 같은 조건으로 다시 검색해도 화면을 새 결과에 맞춘다. 배치만으로 실제 메모 연결을 만들지 않으며, 카드 간격을 근접 연결 임계보다 넓게 둔다.
- 터치로 목록을 열면 검색칸에 자동 초점을 주지 않는다. 검색칸을 직접 눌렀을 때 입력을 시작한다. 목록은 선택 칸 아래 문서 좌표에 고정하며 키보드 높이에 맞춰 위아래로 다시 배치하지 않는다. 입력 글자는 16px로 유지한다.
- 화이트보드 메뉴는 주제별 자료 바로 오른쪽에 놓았다.
- 화면을 닫은 뒤 도착한 저장 응답이 다른 화면에서 새로 보관한 초안을 지우지 않도록 보호했다.

순수 모델·격리 저장소 검사 15개와 가상 자료 브라우저 검사 16개가 통과했다. 터치 첫 열기의 초점, 직접 입력, 페이지 스크롤·화면 높이 변경 때 목록 좌표, 성긴 과거 배치, 반복 검색 후 화면 위치, 늦은 저장 응답을 포함한다. 수정 전 실패와 수정 후 통과를 확인했고 독립 코드 검토도 마쳤다. 실제 아이폰의 운영체제 키보드는 자동 검사로 재현하지 않았으므로 기존 실제 기기 점검 목록에 남긴다. 실제 DB·기기 간 동기화는 실행하지 않았다.
