# 전체 기기 저장 검토 기록 — 2026-10-17

승인된 17단계 계획을 직접 순서대로 구현하고, 마지막에 별도 검토자 한 명이 전체 변경을 검토했다. 검토에서 발견한 중요 문제 7개를 한 차례 수정 과정에서 재현 검사와 함께 해결했다. 추가 재검토자를 호출하지 않았다.

## 검토 결과와 수정

1. 편집창을 연 시점의 기준값을 보존한다. 수집기가 버전을 올리지 않고 서지를 보완해도 오래된 폼이 덮어쓰지 않는다. 최초 전체 저장 전 온라인 경로도 같은 기준을 검사한다.
2. 선행 변경이 확정된 뒤 종속 입력을 보낸다. 연구에 담기는 글과 서지는 선택한 내용과 정확히 비교한다. 충돌에서 서버 내용을 택해도 다른 글이 연구 원문으로 자동 확정되지 않는다.
3. 기기와 같은 비밀정보 제거 규칙으로 편집 기준을 비교한다. 표지를 바꾸지 않았으면 서버의 원래 비공개 URL을 유지하고 불필요한 재다운로드를 하지 않는다. 사용자가 표지를 비우는 변경도 정상 저장한다.
4. 중복 생성으로 서버가 반환한 실제 ID를 종속 입력에 원자적으로 연결한다. 사용자 본문과 재시도 요청 번호는 바꾸지 않는다. 응답 유실 재시도를 검증했다.
5. 다른 기기에서 제외한 책의 대기 편집은 충돌로 보관한다. 제외 상태와 원래 도서를 유지한다.
6. 전체 재구성 후 현재·직전 검증 사본만 남긴다. 참조 없는 큰 값 조각과 오래된 중복 세대를 정리하며, 송신 대기와 충돌 원본은 보존한다.
7. 제한된 운영 역할 생성 절차에 순수 투영 함수 실행 권한을 추가했다. 실제 격리 역할로 권한을 검사했다.

관련 검사: `replica-review-regressions`, `replica-storage-contract`, `replica-outbox`, `sync-commands`, `replica-conflicts`. 오류 재현 뒤 수정과 통과를 확인했다. 전체 단위 검사 415개 통과, 타입 검사·CI 범위 포맷 검사·배포 빌드 통과. 빌드 추적 813건에서 비공개 파일 포함 0건. 실제 DB 사본의 38개 업무 테이블 보존과 동시 쓰기·변경분 검증도 통과했다. 브라우저와 운영 배포의 마지막 결과는 운영 전환 기록에 이어서 남긴다.

## 구현 중 내린 판단과 비용

- 작은 행도 직렬화한 JSON 원문으로 전송한다. 큰 정수·소수와 해시를 보존하기 위해서이며, 실제 조회 때 파싱 한 번이 추가된다.
- 페이지 커서는 인코딩 문자열 대신 실제 위치로 비교한다. UTC와 서울 시간 표현 차이 때문이며, 잘못되면 누락·중복이 생길 수 있어 SQL↔기기 교차 커서를 검사했다.
- 기존 명령 API 위에 로컬 준비·송신 어댑터를 둔다. 임의 행 업로드나 별도 HTTP 체계를 만들지 않기 위해서이며, 어댑터 연결 오류는 실제 SQL·폼 검사로 확인했다.
- 포맷의 줄바꿈은 기존 Windows·Linux 작업 환경을 따른다. 관계없는 파일 수백 개를 다시 쓰지 않기 위해서이며 실행 동작에는 영향이 없다.
- PDF 원본·OCR 파일은 기기 복제에서 제외한다. 사용자가 명시한 범위이며, 원문 열람에는 PC 연결이 필요하다.
- 연구 자료는 버전만이 아니라 선택한 글·서지의 내용 기준값을 우선한다. 서로 다른 글의 버전이 같을 수 있고 명시적인 충돌 해결로 같은 글의 버전이 올라갈 수 있기 때문이다. 잘못되면 원문 출처가 달라질 수 있어 양쪽 선택을 검사했다.
- 현재·직전 검증 사본과 현재 재개 가능한 받기 한 개만 유지한다. 중복 공간을 제한하면서 복구 사본을 남기기 위해서다. 재구성과 겹친 내보내기는 안전하게 실패하면 다시 실행해야 한다.

## 보류한 사소한 지적

없음. 실물 iPhone에서 최초 전체 저장과 이후 변경 왕복을 확인하는 단계는 사용자 기기에서 수행한다. Windows WebKit 시험을 실제 iPhone 확인으로 대신 표시하지 않는다.

## 실제 첫 저장에서 확인한 후속 수정

- 긴 전송 중 SDK의 공식 세션 갱신을 사용하고 계정을 확인한 뒤 만료 요청을 한 번 재시도한다. 인증 서버의 429·502 같은 지연을 로그아웃으로 오인하지 않는다. 세션 응답과 토큰은 복제 자료로 저장하지 않는다.
- 처음 온라인 목록 조회만 잠시 실패했을 때 이미 열린 기기 저장소와 다운로드를 유지한다. IndexedDB 자체가 막힌 경우에만 온라인 전용 안내를 표시한다.
- 전체 집계·검증은 같은 반복 읽기 거래 안에서 테이블별로 나눠 실행한다. 실제 DB 사본에서 세 요청을 동시에 실행하고 15초 제한을 강제했을 때, 기존 집계는 모두 57014로 중단됐고 분할 방식은 모두 35초 이내 완료했다. 개별 쿼리는 13.3초 이하였다.
- 128KiB 이하 일반 표지는 512KiB 이내 페이지에 묶어 받는다. 큰 원본과 이미지의 192KiB 조각 검증은 유지한다.

후속 변경 포함 최종 검사: 단위 422개, 전체 화면 80개 통과. WebKit의 초기 조회 실패·저장소 차단 구분도 통과했다. 빌드·타입·포맷과 813개 추적의 비공개 파일 포함 0건을 확인했다. 별도 생성 자료 16만 행·약 222MiB의 Windows WebKit 전체 저장·중단 재개·재열기 검증이 완료됐고, 준비 후 조회 p95는 49ms였다. 사용자 iPhone에서는 버튼 표시와 첫 저장 진행을 확인받았으며, 실기기 전체 저장·오프라인 재열기·새 기록 왕복 확인은 남아 있다.
