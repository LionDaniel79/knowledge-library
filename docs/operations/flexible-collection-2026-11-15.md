# 서지 수집 실행 방식 및 한도 설정 확대

## 기능

- PDF·로고스별 `예약 없이 연속 실행 / 예약 시각에 실행 / 수동 실행만` 선택.
- 하루 0~10,000권, 한 번 1~10,000권 설정. 10,000은 소프트웨어 설정 상한이며 외부 API의 보장 처리량이 아니다.
- 예약 시각은 한국시간 `HH:mm`을 쉼표로 입력(최대 8개). 기존 설정은 기존 예약 방식과 한도를 유지하도록 호환.
- 내부 배치는 계속 최대 100권. 큰 실행은 작은 배치를 순차 실행한다. PDF 배치별 API 160회·선택 OCR 20쪽 보호, 제공자 호출 원장과 한도 유지.
- 연속 실행은 PDF/Logos를 번갈아 실행. 예정된 예약은 연속 작업보다 먼저 처리. 대상이 없으면 1시간, 지연된 실행은 15분 대기. 정상 실행 후에는 1분 간격.
- 검산이 완료된 빈/부분 배치의 미사용 예약 용량만 반환. 중단·검산 실패한 배치의 보수적 예약은 유지.
- 설정을 저장할 때 방식·시각·두 한도를 함께 저장하고 현황 갱신으로 미저장 입력을 지우지 않음.

## 실제 PC 적용

기존 수집과 OCR의 안전한 대기 지점을 확인하고 실행 파일을 새 버전 폴더로 교체했다. 기존 연결·SQLite·캐시·호출 기록·진행 원장을 재사용한다. OCR을 재개했고 기존 앱 시작 바로가기를 새 버전으로 갱신했다. Windows 예약 작업은 다시 만들지 않았다.

사용자 요청에 따라 두 수집기 모두 **연속 실행, 하루 1,000권, 한 번 100권**으로 시작했다. 설정 화면에서 상한 내에서 수정할 수 있다. 한 번 최대를 늘려도 내부적으로 100권씩 나눈다. 과도한 CPU·외장하드 사용이나 API 잔여량 부족 시 일시정지/한도 축소 가능.

실제 실행 검사에서 이전 통합의 별도 시작 오류도 확인했다. 잠금 함수가 `file:` URL을 Windows 경로로 바꾸기 전에 문자열에 확장자를 붙여 `ENOENT`가 발생했다. URL을 정상 경로로 변환하도록 수정했고 회귀시험을 추가했다. 해당 중단 기록은 비공개 작업 폴더에 보관했다. 이는 기록 부족으로 원인을 확정하지 못한 과거 TypeError와는 다른 오류다.

설치된 실제 설정으로 Logos/PDF `--check`가 통과했고 트레이 호스트에서 실제 Logos 수집이 시작됐다. 중간 확인 시 16권 처리, 자원 오류 0건이었다. 이 수치는 순간 확인치이며 하루 전체 결과나 실제 표지 적용 수가 아니다. PDF는 순차 대기하며, 하루 1,000권 전체 완료와 10,000권 설정의 전체 실처리는 이번 검수 대상이 아니다.

## 검증

- Node 관련 시험 15개: 기존 한도/검산, 연속 실행 순서, 빈 배치 대기, 예약 분·시각, 수동 방식, 설정 상한/변경, 예약 우선, 미사용 용량 반환, URL 잠금과 동시 잠금 검증.
- WPF 빌드와 격리 화면 시험: 실행 방식·한 번 한도·사용자 시각의 저장, 미저장 입력 보존, 기존 일시정지/오류 표시 통과.
- TypeScript 검사 통과. 웹 코드 변경이 아니므로 Vercel 배포하지 않음.
- 외부 API 한도·기존 자격 증명·개인 메모·독서 이력·PDF 원본은 변경하지 않음. OCR의 기존 결과를 초기화하지 않음.

운영 설정과 이전 실행 파일·설정 백업은 비공개 `flexible-collection-20261115` 작업 폴더에 보관한다.
