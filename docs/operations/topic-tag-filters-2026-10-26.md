# 주제·태그 선택 메뉴 관리 — 2026-10-26

통합검색의 ‘메모 검색’과 사유의 지도의 ‘내 기록’에서 같은 주제 선택 메뉴를 사용한다.

- 주제 메뉴를 열면 입력한 글자로 즉시 목록을 좁힌다. 검색창 오른쪽의 ‘생성’은 입력한 이름과 같은 주제가 없을 때 사용할 수 있다. 생성 후 목록에서 선택한다.
- 첫 주제 목록을 읽기 전에는 생성을 비활성화한다. 새로고침 중에는 이전 목록을 유지해 기존 이름의 중복 생성을 막는다.
- 주제 오른쪽 ‘−’는 확인창을 연다. 확인해야 기존 버전을 기준으로 주제를 목록에서 삭제한다. 메모·기존 연결·수정 이력은 보존하며 기존 주제 관리의 복원 기능도 유지한다. 하위 주제가 있는 경우 기존 보호 규칙에 따라 먼저 정리해야 한다.
- 태그 메뉴도 두 화면에서 검색할 수 있다. ‘−’를 누른 뒤 확인하면 해당 태그만 기록에서 제거한다. 메모 내용은 유지한다. 취소는 저장 요청을 보내지 않는다.
- 선택한 주제를 삭제하면 필터를 전체로 바꾸며, 다른 주제를 삭제한 경우 기존 선택과 검색 입력을 유지한다. 메모 검색에 이미 적용한 조건도 삭제 대상에 해당하는 주제·태그만 해제한다.
- 메모 검색의 ‘검색’ 실행과 달리, 주제 팝업의 글자 입력은 목록 검색만 한다. Enter로 메모 검색을 제출하거나 주제를 만들지 않는다.

구현은 공통 TopicFilter, 기존 FacetPicker의 선택적 관리 버튼, 기존 주제 명령·태그 일괄 삭제 명령을 사용한다. 주제 버전과 태그 fingerprint를 유지한다. 주제 선택용 경량 온라인/기기 응답에 버전 번호를 추가했으며, 기기 메뉴를 열 때 원문 검색 색인을 준비하지 않는다. DB 구조나 인증 설정은 변경하지 않는다.

모바일 주제 메뉴의 첫 터치는 목록을 열고, 검색 입력을 다시 누르면 키보드를 여는 기존 방식을 유지한다. 생성 버튼은 검색창 오른쪽에 배치하고, ‘내 기록’의 필터는 이름이 있는 CSS 선택자로 위치를 지정해 새 메뉴로 인한 겹침을 막는다.

검수는 고립 DB·IndexedDB와 Chromium/WebKit 가상 자료로 수행한다. 주제 버전·생성·삭제·취소·오류, 늦은 목록 갱신, 생성 직후 삭제, 메모 보존, 다른 검색 조건 보존, 모바일/PC 배치를 확인한다. 실제 개인 자료를 시험 삼아 만들거나 삭제하지 않는다. AI 호출과 OCR 작업 변경도 없다.

검증 결과: 관련 DB·기기 저장소 검사 17개, Chromium/WebKit 화면 검사 32개 통과. TypeScript 검사와 운영 빌드 통과. 배포 추적 파일 18,123개 중 비공개 자료 경로는 0개였다. 별도 검토에서 발견한 초기 로딩·목록 갱신 중의 중복 생성 가능성은 실패 재현 검사를 추가하고 보완했다. 배포 결과와 식별값은 별도 운영 기록에 남긴다.
