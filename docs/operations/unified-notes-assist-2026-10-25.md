# 내 기록 통합·AI 사고 보조 (2026-10-25)

## 사용 흐름

1. 사유의 지도 → 내 기록에서 종류·도서 분야·도서명·주제·태그·검색어를 함께 고른다. 도서명은 목록을 연 뒤 검색해 선택한다. 기록 제목을 누르면 기존 편집 창이 열린다. 태그 관리는 태그 목록에 있고, 휴지통은 맨 아래에 있다. 표시 개수는 아래 페이지 표시 오른쪽에 있다.
2. ‘필요할 때 AI 도움’을 열어 종합 검토, 메모 연결, 주제 연결, 새 주제, 글감·목차 중 도움 방향을 고른다.
3. ‘분석할 기록 확인’을 눌러 전송 범위와 비용 상한을 확인한다. 이 단계는 AI를 호출하지 않는다. 현재 조건의 최대 200개 후보에서 최대 24개 대표 기록을 고른다. 긴 기록은 검색어 주변 또는 앞부분을 발췌하고 총 약 10,000자 안에서 보낸다. 책/PDF 전체를 분석한 결과가 아니다.
4. ‘이 기록으로 AI 도움 요청’을 누른다. 완료된 요청 행을 펼쳐 제안과 근거를 읽고 원하는 항목만 저장한다. 메모 연결·주제 연결은 실제 관계로, 새 주제는 해당 기록의 분류로, 글감은 메모 상자의 글감 묶음/목차/당시 원문으로 저장한다. 원본 메모 내용은 바꾸지 않는다.
5. 요청 행 오른쪽 휴지통은 목록에서 숨긴다. 이미 저장한 연결·주제·글감과 비용 장부는 보존한다. 대기 요청은 취소할 수 있다. 전송 중/비용 미확인 상태는 처리 또는 비용 확인을 마친 후 삭제한다.

## 모델과 비용

‘모델 선택’은 접힌 설정이며 선택은 이 기기/계정에 기억한다. 기본 GPT-6 Luna, 선택 GPT-6.1 Sol 모두 중간 추론을 사용한다. 모델 접근 권한은 실제 계정에 달려 있다. 실패 후 다른 모델을 자동 호출하지 않는다. 기존 API 키를 재사용하며 브라우저에 키를 보내지 않는다.

월 US$5 상한은 그대로다. 기존 건당 한도로 선택 모델의 예상 최대 비용을 감당하지 못하면 표시된 금액으로 직접 조정하는 버튼이 나타난다. 조정은 월 한도를 올리지 않으며 AI 호출과 별도다. 이번 구현에서는 실제 유료 호출이나 본인 DB 정책 변경을 실행하지 않았다.

## 구현 판단과 한계

- 대표 기록만 보내는 것으로 범위를 정했다. 미전송 기록의 연결을 놓칠 수 있으므로 주제·도서·태그를 바꾸거나 범위를 좁혀 다시 검토한다.
- 한 응답의 근거 없는 제안은 제외하고 독립적으로 검증된 제안은 남긴다. 남은 제안에도 사람의 의미 판단이 필요하다. 근거 문장의 일치는 추론의 타당성을 보증하지 않는다.
- 삭제 확인 ID를 기기에도 기억해 오래된 목록의 재등장을 막는다. 새 기기로의 전달은 서버의 숨김 상태와 기존 동기화에 의존한다. 기기별 표식은 최근 1,000개까지만 보관한다.
- 기존 정책 안에서 명시적으로 건당 한도를 조정할 수 있게 했다. 더 큰 요청은 예산 소모가 빨라질 수 있으나 월 상한은 유지한다.
- 새 DB 구조와 별도 분석 시스템을 만들지 않고 기존 자료 질의·요청·예산·관계·연구 자료를 확장했다. 기존 요청/결과와 이전 가격표 환경 설정을 호환한다.

## 검수와 반영

고립 DB/가짜 API 응답 및 모의 PC·모바일 화면으로 검사한다. 개인 온라인 DB와 실제 기기 동기화, 실제 OpenAI 모델 호출은 확인하지 않았다. 11월 1일 검수 항목은 `sync-acceptance-2026-11-01.md`에 추가했다. 외장 PDF·안정 PC 서버·OCR 실행은 변경하지 않는다. 외장하드의 exFAT 제한으로 이 PC의 Next 빌드는 사용하지 않으며 최종 빌드는 Vercel에서 확인한다.
