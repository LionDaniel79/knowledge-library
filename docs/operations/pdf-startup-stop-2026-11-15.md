# PDF 시작 단계 중단과 재개

## 발생

2026-11-15 07:14:33 한국시간에 PDF 수집이 시작 단계에서 `Error`로 종료했다. 직전 Logos 배치는 100권 조사, 23권 유력 후보, 검토 2권, 후보 없음 75권으로 정상 종료했다. Logos의 `applied=100`은 후보 없음 처리 저장도 포함하므로 100권의 표지가 생겼다는 뜻이 아니다.

PDF 당시 보고서는 scanned/processed/API/OCR/apply가 모두 0이었다. 원본을 처리하기 전 DB 목록·표지 정보 조회 단계에서 중단했으며, 공유 보호 장치가 두 수집을 멈췄다. 당시 로그는 오류 이름만 저장해 정확한 문구·원인을 확정할 수 없다. 실제 실행 시간은 DB 응답 시간 초과 가능성과 부합하지만 확정 진단으로 보고하지 않는다.

## 확인 및 수정

- 운영 DB의 동일 목록 조회를 읽기 전용으로 재검사: 약 3.3초, 표지 참조 조회 약 1.0초로 정상. 기존 오류 재현 안 됨.
- PDF 시작의 읽기 전용 조회에만 확인된 일시적 오류를 1초/2초 간격으로 최대 두 번 재시도. 인증·프로그램 오류는 재시도 안 함. DB 쓰기/적용 트랜잭션을 재실행하는 로직 아님.
- 오류 단계·원인 코드·안전한 소스 위치를 기록하고 PDF 조사 보고서에서 상위 중단 기록으로 전달. 키/URL/개인 경로/원문 오류 메시지 제외.
- 재시도 가능한 연결 오류는 UI에 원인 안내와 `중단 후 다시 시도` 버튼을 표시. 사용자의 확인은 해당 중단 시각과 연결해 다른 오류나 오래된 요청을 해제하지 못하도록 함. 중단 이력 보관, 중복 요청 방지, 일일/한 번 한도 유지.
- 원인 불명·인증·프로그램 오류는 계속 보호 중단. 파일을 지워 강제 재개하지 않음.

## 실제 검증과 적용

설치 소스로 PDF 1권 유한 실행 성공. 신규 표지·저자·출판사·책 소개·참고 ISBN 각 1건 적용. 기존 저장 후보 사용으로 외부 서지 API 호출 0회, 이미지 요청 1회. 선택 OCR 0쪽. 기존 자동 적용/수정 이력 트랜잭션 사용.

실제 조사 ID와 기존 원장의 중복 여부를 확인해 1권을 원장에 반영하고, 이전 실패의 보수적 예약은 초기화하지 않았다. 기존 중단 기록은 비공개 작업 폴더에 보관했다. OCR 쪽 완료 뒤 대기 상태에서 UI를 새 릴리스로 교체하고 OCR·서지 수집을 재개했다. 사용자 설정은 기존 연속 방식·하루 1,000권·한 번 100권을 유지한다.

관련 Node 13개/TypeScript 7개 시험, WPF 빌드·격리 화면 검사 및 TypeScript 검사 통과. 전체 하루 배치 완료와 과거 오류의 정확한 원인은 이번 검사로 확인한 것으로 표시하지 않는다. 웹 변경이 아니므로 Vercel 배포 없음.
