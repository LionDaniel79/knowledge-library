# 서지 수집 중단 점검 및 재개

## 확인한 사실

- 이전 중단 기록은 2026-11-14 Logos 수집의 `TypeError` 종류만 보관했다. 메시지·원인 코드·발생 지점이 없어 당시 정확한 원인을 확정할 수 없다.
- 현재 저장 후보의 사본을 사용한 오프라인 실행에서는 오류가 재현되지 않았다. 원본 캐시와 운영 DB에는 이 검사로 쓰지 않았다.
- 제한된 실제 연결 검사와 수집은 정상 종료됐다. 따라서 과거 오류를 현재도 계속 발생하는 프로그램 결함이나 네트워크 장애로 단정하지 않는다.

## 변경

`collection-failure.ts`와 기존 Logos 실패 콜백에 발생 단계(체크포인트/조회/판단/적용), 원인 코드, 소스 파일명·행 번호를 기록한다. API 키, URL, 개인 경로, 원문 오류 메시지는 기록하지 않는다. 프로그래밍 TypeError를 무조건 네트워크 오류로 취급하거나 기존 전역 오류 중단을 우회하지 않는다.

Windows 실행 소스에도 이 진단 변경을 적용했다. 기존 미커밋 내용과 원본은 비공개 작업 폴더에 보존했다. 실행 중인 OCR과 앱을 재시작하지 않았다. 수집기는 매번 최신 스크립트를 새 자식 프로세스로 실행한다.

## 실제 소량 검증

| 자료 | 조사 | 후보 없음 | 원본·범위 보류 | 새 표지/자동 서지 보완 | 오류 |
|---|---:|---:|---:|---:|---:|
| Logos | 4 | 4 | 0 | 0 | 0 |
| PDF | 6 | 1 | 5 | 0 | 0 |

Logos 3권은 개발 소스, 마지막 1권은 실제 Windows 설치의 실행 소스로 검증했다. PDF는 3권씩 두 번 검사했다. PDF 보류 5권은 확인되지 않은 원본 연결 또는 기존 처리 범위에 따른 것이며, 없어진 파일이라고 확정하지 않았다. 강제 처리·OCR 재실행·새 ISBN 확정은 하지 않았다.

Logos 통계의 `applied`는 후보 없음 처리 결과 저장도 포함한다. 이를 표지/서지정보 자동 보완 성공으로 집계하지 않는다. 이 검증에서 새 표지 적용은 0건이다. 당시의 당일 공통 API 원장 집계는 정보나루 6회, 예스24 5회다(연결 검사 포함).

## 재개

정상 종료와 조사 ID의 중복 여부를 확인해 실제 조사 Logos 4권/PDF 6권을 당일 기존 원장에 반영했다. 기존 `halted.json`은 비공개 복구 폴더에 보관한 뒤 활성 중단 상태만 해제했다. 기존 트레이 호스트가 재시작 없이 이를 읽고 정상 예약 대기로 돌아간다.

일일 한도는 사용자 설정인 Logos 300권·PDF 100권을 유지한다. 앱이 실행 중이면 Logos 09:00/21:00, PDF 15:00에 남은 한도 내에서 처리한다. 옛 Windows 예약 작업은 비활성 상태를 유지해 중복 실행을 방지한다.

## 검증과 남은 사항

- 진단 정보의 비밀값 제거·오류 단계·허위 성공 방지와 기존 Logos 수집 관련 시험, TypeScript 검사 수행.
- 개인 메모·독서 이력·PDF 원본·기존 OCR 색인에는 이 작업으로 변경을 가하지 않았다. 일반 OCR 백그라운드 진행은 계속된다.
- 당시 TypeError의 정확한 원인은 여전히 미확정이다. 현재 실행 정상 확인과 과거 원인 확정은 구분한다.
- 향후 전체 일일 배치의 완료 및 새 표지 적용 성공률은 이번 소량 검사로 보장하지 않는다. 재발하면 기존 보호 중단과 새 진단 정보를 사용한다.
- 웹 기능 변경이 아니므로 Vercel 재배포하지 않는다.
