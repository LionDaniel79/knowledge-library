# 기기 서재 시작 시간 개선

## 2026-10-18 클릭·메모 재열기 지연

실제 계정의 구분된 점검 메모로 작성·수정을 시험했다. 저장 버튼 응답은 약 0.3초였으나 신규 창과 기존 메모 재열기는 화면 동작 자체가 수 초간 밀렸다. 전체 공급자 정리 자료의 파싱·정렬·색인 준비가 화면 실행 공간에서 동작하고, 한 메모 조회도 전체 목록을 기다리던 경로를 확인했다.

IndexedDB의 같은 DB·같은 소유자에서 읽기 전용 작업자를 열어 목록·개요·검색·세부 정보 준비를 수행한다. 큰 색인을 화면으로 전송하지 않고 조회 인수와 필요한 결과만 교환한다. 기기 송신 대기의 원본 저장·소유자 검증·충돌 처리는 유지한다. 작업자 불가 시 기존 로컬 조회를 사용하며, 창·계정 종료는 대체 조회 중인 요청까지 취소한다. 전체 캐시 조회 도중 수정이 발생해도 체크포인트를 다시 검사하고 더 오래된 색인으로 되돌리지 않는다. 단일 메모는 해당 메모와 휴지통 행만 확인한다. 신규·수정 기록은 전체 재조회 전에 최근 기록 순서에 즉시 반영한다.

검수는 별도 생성 자료로 대량 공급자 정보 조회 중 클릭·입력, 오프라인 검색, 저장 직후 작업자의 최신 메모 조회, 작업자 오류와 계정 종료를 확인한다. 실제 계정 점검은 식별 가능한 테스트 메모 한 건만 작성·수정·재열기 후 휴지통으로 옮겨 목록에서 제거한다. 기존 휴지통의 다른 기록은 삭제하지 않는다. 실제 점검 결과는 PC 비공개 운영 영수증에 남기며 iPhone 실기기 측정과 구분한다.

운영 배포는 시험과 동일하게 Webpack으로 빌드한다. 기본 Turbopack 빌드는 작업자 소스를 JavaScript 대신 `.ts` 미디어 파일로 내보내 작업자 실행이 실패하고 화면의 대체 조회로 돌아갔다. `npm run build`에 Webpack을 명시하고, 정적 산출물에 컴파일되지 않은 TypeScript가 남으면 빌드를 실패시킨다. JavaScript 작업자 파일도 오프라인 화면 목록에 포함하는 검사를 유지한다.

## 이전 시작 화면 개선

기존 진입 화면은 로그인 확인, IndexedDB 열기, 전체 검색 색인 읽기/구성, Worker에 검색 자료 복사까지 기다릴 수 있었다. Worker 로딩 오류가 초기화 요청 이전에 발생하거나 응답이 없으면 준비가 끝나지 않는 경로도 있었다. 이는 코드에서 확인한 지연 경로이며 실제 iPhone의 지연을 별도로 계측한 결과는 아니다.

이제 계정별로 마지막 서재의 작은 표시용 사본을 저장해 재진입 때 먼저 표시한다. 완전한 38개 업무 테이블과 이미지 사본은 기존 IndexedDB에 그대로 유지한다. 표시용 사본은 100만 문자 이하로 제한하고, 외부 표지 주소·공급자 원문·인증정보·PDF 원본·편집 중 초안을 포함하지 않는다. 손상·저장공간 부족·차단이면 기존 조회로 돌아간다. 가져온 책의 `cover:null`도 허용한다. 새 버전에서 한 번 연 이후부터 이 빠른 표시 사본을 사용할 수 있다.

업데이트 직후 표시용 사본이 아직 없는 첫 실행도 별도로 처리한다. 1.8초 뒤까지 첫 화면이 없고 보통의 온라인 첫 조회가 진행 중인 경우가 아니면, 같은 계정의 로그인 확인 뒤 작은 온라인 서재 개요를 요청한다. 로그인 확인 없이 데이터를 요청하거나 서버 응답으로 기기 원본을 덮어쓰지 않는다. 미전송 입력이 확인된 경우 해당 독서 진행을 겹쳐 표시하며, 늦은 응답이 이미 표시된 기기 화면을 덮지 못하게 한다. 정상적인 기기 조회가 먼저 끝났을 때는 이 추가 요청을 보내지 않는다. 첫 표시 사본을 받은 다음 재진입은 이를 즉시 사용한다.

로그인 확인과 기기 저장소 열기는 동시에 진행한다. 표시 중인 계정의 확인이 끝날 때까지 서버 조회/저장을 보류하며 계정 변경·접근 거부 시 이전 화면을 닫는다. 저장소 연결 전후에 같은 앱/편집창을 유지하고, 비동기 응답이 이전 계정을 다시 표시하지 못하도록 검사한다. 전체 책 정보를 읽기 전에는 기존 책 수정 버튼을 활성화하지 않아 표시용 사본에서 생략한 표지가 지워지지 않게 한다.

첫 화면·도서 목록·독서 현황·메모 조회는 별도의 목록 색인을 사용한다. 서지·표지·분류·미전송 입력·독서 통계는 동일하게 보존하고, 방대한 공급자 소개·목차·연구 자료를 검색용 문장으로 복제하는 작업은 통합 검색을 실제로 요청할 때만 한다. 목록 색인은 전체 검색 색인과 따로 저장하고 변경 순번으로 각각 갱신한다. 첫 화면을 위한 조회는 Worker 초기화를 기다리지 않는다. Worker는 실제 검색 시 준비하고 2.5초 안에 응답하지 않거나 로딩에 실패하면 같은 기기 색인으로 조회한다. 홈에서 쓰지 않는 도서 목록 조회는 생략하되 상단 검색과 도서 목록에서는 계속 조회한다. 최신 내용과 변경분 동기화는 별도로 진행한다. 전체 받기 진행 중인 자료를 완료라고 표시하지 않는다.

검수는 실제 소스와 별도 합성 계정을 사용한다. 로그인과 DB 열기를 의도적으로 멈춘 상태의 첫 표시, 연결 도중 작성 중인 글 보존, 다른 계정으로의 전송 차단, 거부된 계정의 화면 제거, 불완전한 표지로 편집 불가, 홈 검색, Worker 실패/무응답 대체를 확인한다. 실제 iPhone의 완전 저장·오프라인·왕복 수정 검수는 기존 계획의 미완료 항목으로 남는다.

검증 결과: 단위 검사 432개, Chromium 전체 흐름 93개, 390px WebKit 시작·오프라인 검색 흐름 9개 통과. 형식·타입 검사와 운영 빌드 통과, 배포 산출물 추적 814건/비공개 파일 0건. 한 번의 독립 검토에서 발견한 계정 확인 전 서버 요청, 가져온 표지의 null 값, 불완전한 책 수정, 홈 검색 누락을 재현해 보완했다. 완전한 기기 사본이 있을 때 서버 목록을 읽지 않는 기존 검사도 유지한다. 이 결과를 실제 iPhone의 초 단위 측정값으로 해석하지 않는다.
