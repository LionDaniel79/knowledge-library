# 2026-11-01 동기화 일괄 검수

사용자 지시로 11월 1일까지 실 동기화 검사를 보류한다. 2026-10-22 한도 안내의 예상 복구 시점은 한국시간 11월 1일 오전 9시이며 실제 가용성을 다시 확인한다. 요금제 변경·기기 자료 초기화·전체 재다운로드를 선행하지 않는다.

## 기존 보류 항목

- PC 메모 1개·아이폰 메모 2개가 양쪽에서 같은 3개로 보이는지, 한쪽 미전송분을 잃지 않는지.
- 메모 작성/수정/삭제/휴지통 전체삭제·태그 삭제, 읽은 쪽/완독, 책장·분야 변경의 왕복.
- 저장 직후 화면 반응, 뒤에서 변경분만 전송, 읽는 책 순서 유지.
- 오프라인 작성 후 복귀, 같은 메모 수정 충돌, 응답 유실 재시도·중복 방지.
- 재로그인·창 닫기·홈 화면 재추가 후 기존 기기 자료 재사용. Safari와 홈 화면 앱의 저장소 차이, 중복 저장소 정리 시 미전송 자료 보존.
- 전체 자료 범위/표지/목차/이력·후보·제외 자료, PDF 원본/OCR은 외장하드에 유지.
- 최초 다운로드 재개·진입 속도·다중 탭·오래된 기기 복귀·세션 계정 경계.
- 전송량 원인 측정과 변경분 동기화: 반복 전체 조회·표지 base64·이력·검증 조회의 실제 사용량.

## 화이트보드 추가 항목

- 028_whiteboard.sql 및 제한 역할 권한을 적용한 뒤 메타/범위/백업 등록 확인. 코드만 준비된 상태를 적용 완료로 간주하지 않는다.
- 계정별 보드 좌표·접힘·수동 묶음·그룹 연결의 PC→아이폰→PC 변경분 왕복.
- 화이트보드의 메모 연결이 실제 library_connections 및 사유의 연결에 반영되는지, 연결 해제·기존 다른 관계 보존·역방향 중복 방지.
- 연결선 선택 → 끊기 → 되돌리기의 PC·아이폰 왕복과 오프라인 대기 명령을 확인한다. 접힌 묶음의 한 선에 여러 메모 관계가 있어도 선택한 쌍만 해제하고, 묶음 선 해제는 메모·묶음 구성을 보존해야 한다. 실제 iPhone Safari에서 확대·축소한 선의 터치와 고정 크기 해제 도구도 확인한다.
- 오프라인 연속 이동/연결 후 재접속: 같은 보드 충돌은 조용히 덮어쓰지 않고 미전송 입력 보존.
- 보드 충돌에서 서버 배치 선택 시 같은/낮은 버전도 반영. 자기 저장의 늦은 응답은 새 편집을 충돌로 오인하거나 되돌리지 않아야 하며, 배치와 충돌 해결 표식은 같은 기기 자료 버전에서 읽는다.
- 연결을 만든 뒤 다른 곳에서 관계·이유가 바뀌면 되돌리기는 충돌로 멈추고 최신 판단을 보존한다. 배치만 이동할 때 책·메모 전체를 다시 읽지 않는지도 확인한다.
- 아이폰 Safari·홈 화면 앱에서 드롭다운을 열 때는 목록만 표시하고, 검색칸을 직접 눌렀을 때만 키보드가 나타나는지 확인한다. 키보드 열기/닫기·스크롤 중 선택 칸과 목록의 위치 관계, 선택 조건 유지도 확인한다. 실제 기기에서만 확인 가능한 항목이다.
- 좁힌 검색 결과의 메모 간격·재검색 화면 맞춤·수동 배치 보존과, 화면을 빠르게 닫고 다시 열 때 늦은 저장 응답이 새 초안을 덮지 않는지 함께 확인한다.
- 기존 전체 저장이 끝난 기기에도 새 보드 자료가 증분으로 들어오는지, 보드가 없는 기기는 빈 보드에서 시작하는지.
- 주제 변경·메모 휴지통·복원과 그룹 필터/연결, 복수 주제의 동일 메모.
- 기존 sync/replica 검사 및 화이트보드 변경 대기 검사 실행. 현재는 실행 보류.
- `tests/deferred/whiteboard-sync.test.ts`는 `LIBRARY_RUN_DEFERRED_SYNC=1`을 설정한 11월 1일 검수에서만 실행한다. 새 테이블 적용 전의 기존 메타·분할 받기·범위 검증·백업 호환성과 적용 후 보드 명령/공개 행도 확인한다.

검수용으로 분리한 자료를 사용하고 종료 후 정리한다. 사용자 실제 기록은 삭제하거나 초기화하지 않는다. 자동 확인이 가능한 항목을 먼저 끝내고 실제 아이폰에서만 가능한 확인만 사용자에게 요청한다.

## 주제별 자료 개선 후 기기 검수
- PC·아이폰의 기존 전체 저장을 유지한 상태에서 분야/주제/자료 종류/정렬이 같은 자료를 반환하는지 확인한다. 기기별 표시 순서는 계정별 UI 설정이며 교차 기기 동기화 대상이 아니다.
- 오래된 기기 검색 캐시의 기록 시각 키 보완이 전체 재다운로드 없이 기존 로컬 자료를 사용하는지, 새로 작성한 기록과 주제 배정·거절·삭제 후 페이지/정렬이 갱신되는지 확인한다.

## 메모 상자·글감 엮기 추가 검수 (10월 25일)

- 오프라인에서 제목 없는 기록을 주제와 함께 작성하고 기존 메모에 연결한다. PC·아이폰에서 재연결 후 메모/주제/연결이 한 번씩 나타나는지 확인한다. 전송 중 실패·중단 시 부분 저장과 중복이 없어야 한다.
- 기존 메모의 주제 편집이 다른 기기와 충돌하면 내용과 선택 초안을 보존한다. 이전 버전의 기록 입력 화면이 주제 필드를 보내지 않을 때 기존 분류가 지워지지 않아야 한다.
- 새로 만든 주제/메모/글감 묶음의 임시 ID가 서버 ID로 치환될 때 topicChanges, relatedNotes, 순서 항목의 참조가 유지되는지 확인한다. 하위 행 ID는 requestId 기반으로 동일해야 한다.
- 메모 상자의 연결 이유·관계 수정과 관련 기록 추가, 직접 거절한 주제/삭제 주제/휴지통의 표시를 확인한다. 주제 묶음의 시각적 연결과 메모 사이의 근거 연결 수를 구분한다.
- 제목·목차 수정의 동시 편집 충돌, 3개 이상 글감의 순서 이동을 원자적으로 저장하는지, 배치 미지정인 과거 자료도 순서대로 정렬되는지 확인한다. 원본 메모와 담을 당시의 스냅샷·출처·쪽수는 보존한다.
- 기기 전체 자료에 저장된 library_research, library_research_items, library_research_placements, 주제와 연결을 재사용하는지 확인한다. 새 테이블이나 전체 재다운로드는 이 변경에 필요하지 않다.
- 실제 iPhone Safari/홈 화면 앱에서 기록 입력 주제 선택, 모달 키보드·스크롤 안정성 및 글감 .md/.txt 파일 저장을 확인한다. 이 전까지는 고립 DB/모의 브라우저 검수만 완료로 기록한다.
