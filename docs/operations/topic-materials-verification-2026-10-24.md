# 주제별 자료 개선 검증

## 최종 동작

- 나의 주제는 목록과 주제 사이 연결 다음에 작은 접기 영역으로 표시한다. 위·아래 화살표로 순서를 바꾸며 본인 계정의 현재 기기에 저장한다. 주제 필터와 주제 분류의 순서도 바뀐다.
- 자료 종류는 내 기록 / 책 / 두 종류 함께를 뜻한다. 기본은 내 기록이다. 도서 분야는 연결한 책의 KDC 큰 분류이며, 세부 번호와 책 없는 미분류도 처리한다.
- 분야 옆에 주제, 표시 개수 왼쪽에 정렬을 둔다. 휴대폰에서도 두 쌍의 좌우 배치를 유지한다. 선택 칸의 높이는 모두 44px다.
- 주제는 직접 분류와 책의 주제를 참고하며, 메모에서 거절한 주제나 삭제한 주제는 다시 포함하지 않는다. 표시상 상속은 실제 메모 분류를 자동 수정하지 않는다.
- 최신순·오래된 순은 작성/등록 시각, 분야별은 KDC, 주제별은 주제명, 책별은 연결된 책 이름 기준이다. 전체 결과를 먼저 정렬하고 페이지를 나눈다. 기존 다른 메뉴의 기본 메모 우선 정렬은 보존한다.

## 원인과 수정

기존의 직접 주제 배정만 참조하던 필터가 책 주제의 메모를 놓쳤고, 분야의 세부 번호를 큰 분류와 직접 비교했다. 자료 조회를 SQL UNION과 같은 기준의 기기 순수 모델로 바꾸었다. 서버는 페이지 분량만 반환하며 전체 서재를 내려받아 정렬하지 않는다.

검토에서 확인한 마이크로초 정밀도, C 문자 정렬과 여러 책장 검색 회귀를 각각 실패 검사로 확인하고 수정했다. 기존 timestampKey/binaryCompare를 사용한다. 이전 기기 캐시의 기록 시각 키는 해당 자료 메뉴를 사용할 때 기존 기기 원본에서 보완한다. 전체 재다운로드나 서버 스키마 변경은 없다. 내부 정렬 키는 화면 응답에서 제거한다.

각 메모마다 전체 주제 소속을 반복 조회하던 LATERAL을 사전 집계 JOIN으로 바꾸었다. 검토자의 동일한 3,000개 기록·소속 고립 PGlite 예제에서 count/page가 각각 약 2초에서 19·20ms로 줄었다. 실제 운영 서버 지연을 측정한 수치는 아니다.

## 확인 범위

- 고립된 DB·순수 기기 조회 검사 12개 통과. 분야·주제·명시 거절·삭제·종류·다섯 정렬·페이지 경계·계정 분리·시각 정밀도·문자 정렬·기존 검색을 포함한다.
- 모의 브라우저 14개 통과. 주제 관리 마지막 배치, 순서 재열기 보존과 계정 구분, 390/1440px 좌우 배치·높이·가로 넘침, 수정·삭제·복원과 기존 메뉴 동작을 확인했다.
- TypeScript 통과. 독립 검토와 지적 수정 후 후속 검토 완료.
- Vercel 배포 입력 약 4.75MB 검사에서 비공개 파일 포함 0건. E exFAT의 로컬 Next 빌드 제약은 알려진 상태이므로 최종 빌드는 Vercel Linux에서 확인한다.
- 실제 사용자 자료 수정, 운영 DB·기기 동기화 검사는 하지 않았다. 11/1 검수 목록에 기록했다. OCR·PDF 서버는 유지한다.
