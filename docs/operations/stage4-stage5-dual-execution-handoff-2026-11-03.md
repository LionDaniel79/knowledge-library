# 4단계 종료 기준과 5단계 공동 실행 인계 — 2026-11-03

> 사용자가 확정한 범위가 우선한다. 4단계는 **기능 개발·검수**, 5단계는 **실자료 등록·전환**이다. 원본 PDF/SQLite/OCR, 독서 기록 및 PC 서버는 보존한다.

## 1. 데이터 기준

- Logos 서재 XML: 전체 2,620개/55종. 책과 읽는 텍스트 간행물 2,418개/48종을 등록 대상으로 한다. 영구 소유 2,246개, 임시 소유 172개. 7개 명백한 비도서 자료 유형 202개(미디어 컬렉션 63, 코스웨어 미디어 컬렉션 17, 인터랙티브 45, 데이터셋 설명서 69, 구 시각화 6, 성경 인물 도표 1, 성경 장소 지도 1)는 제외한다. 설교집, 주석, 성경, 사전, 신학, 코스웨어 교과서 및 텍스트 학술지·잡지는 포함한다.
- 영구/임시 라이선스를 보존한다. `Edition` 값(예: `Logos 연구`)은 개정판을 입증하는 서지판 표기가 아니므로 임의로 해석하거나 기존 도서와 합치지 않는다.
- 기존 Neon PDF 문서: 9,321건. 로컬 PDF: 9,319개. 선택 폴더의 물리 파일 4,109개, 고유 문서 ID 4,108개(추가 사본 1개).
- 지정 로컬 폴더: `E:\전자도서관\기독도서`, `E:\전자도서관\일반도서` 및 각각의 하위 폴더. 로컬 검색 범위 전체와 웹 등록 범위를 혼동하지 않는다.
- 이동 검산 결과 5,210개 기존 ID 대응, 미발견 3개는 수동 검토. 9,321개 전부 자동 보관·삭제 승인으로 해석하지 않는다.

## 2. 4단계 구현과 검증 대상

1. **Logos:** Excel XML 브라우저 파서와 서버의 48종 텍스트 자료 허용 목록 및 7종 비도서 제외 목록, Resource ID 기반 중복 방지, 영구·임시 구분, 기존 판본 충돌 미리보기, 확인된 표지 HTTPS URL 등록 및 조회.
2. **PDF 폴더 동기화:** Windows 기기 인증키 발급·철회, 지정 두 루트의 전체 검사 결과를 `start/items/seal/preview` manifest v2로 전송할 서버 API, 수량과 canonical SHA-256 digest 검증, 오너·도서 버전 검증.
3. **기존 PDF 보관·재등록:** 잠긴 서버 트랜잭션에서 선택한 문서를 동일 `document_id`로 등록하고 나머지 기존 PDF 도서는 `library_book_exclusions.kind='pdf_archive'`로 **가역 보관**한다. 원본 `library_books`, `library_documents`와 노트·독서 기록·원본 PDF·OCR을 **삭제하지 않는다**. 보관 후 다시 선택하면 같은 ID로 복원한다.
4. **검토 화면:** `/desktop/review`에서 수량·누락·버전 충돌·연관 기록 및 보관 대상 개수를 확인한다.

**실제 쓰기 차단:** `LIBRARY_STAGE5_WRITE_ENABLED=true`를 별도로 설정하기 전까지 Logos/표지 등록 및 PDF 보관·재등록 실행 요청을 거절한다. 이 플래그를 4단계 개발 과정에서 운영 서버에 설정하지 않는다. SQL 마이그레이션을 운영 DB에 자동 적용하지 않는다.

## 3. 5단계 역할 분담

### ChatGPT (GitHub·웹앱·Neon 측)

- GitHub 브랜치와 PR의 TypeScript/SQL/API/화면 코드·자동시험을 검토하고 병합 조건을 관리한다.
- 시험용 Neon DB에서 `db/035` 적용, 전체 롤백과 휴지통/동기화 복원 검증, 사용자 소장기록을 포함한 무결성 검사. 운영 데이터 수정 전 외부 백업 복구를 확인한다.
- 실제 Logos XML의 2,418개 대상 자료에 대해 DB 조회·미리보기·중복 판본 검토. 기존 정보는 임의 덮어쓰기 금지.
- 9,321건 기존 Neon 문서와 Windows가 제출한 4,108개 고유 ID를 대조한다. 특히 미발견 문서 3개·추가 사본 1개의 처리를 별도 확인한다.
- 승인 후 단계별 실제 등록/보관을 실행하고, 모바일 동기화·재로그인·오프라인 복구를 검수한다. 이 과정에서 PC의 원본을 직접 열람했다고 주장하지 않는다.

### PC Windows Codex (로컬 파일·검색기 측)

- 기존 `dev/windows-pdf-stage3` 코드/검수 보고서와 운영 SQLite의 **읽기 전용 사본**을 사용한다. `E:\전자도서관` 실제 파일 존재·SHA-256·안정 문서 ID를 검산한다.
- 지정된 `기독도서`와 `일반도서`의 하위 폴더를 포함한 4,109개 물리 PDF를 재스캔하고 4,108개 문서 ID와 사본 관계를 재검증한다.
- 서버의 기기 토큰을 Windows DPAPI 등 보호된 저장소에 저장하고 HTTPS로 manifest v2만 전송한다. API payload에는 원본 PDF 바이트, OCR 본문, 개인 절대/상대 경로, 로컬 파일 해시를 포함하지 않는다.
- 서버 미리보기의 누락/버전 충돌을 로컬 검산 기록과 대조하고, 불일치가 있으면 실행을 중단한다. 로컬 원본이나 SQLite 색인을 삭제·재작성하지 않는다.
- 5단계 실행에 앞서 로컬 스캔 결과(`scanComplete`, `rootsAvailable`, `physicalByRoot`, `copiesByRoot`, `itemsDigest`)와 실패/재시도 보고서를 제출한다.

### 사람이 명시적으로 승인할 최종 분기

- 데이터 백업과 **실제 복구 시연**이 완료되고, 9,321건 대조·선택 자료 검수·타 기기 동기화 영향 분석이 끝난 뒤, 생산 DB에 대해 실행 여부를 별도로 승인한다.
- 승인 전 `LIBRARY_STAGE5_WRITE_ENABLED`는 꺼 두고, 단순 manifest 제출이 쓰기 권한을 뜻하지 않게 한다.
- 원본 PDF/SQLite/OCR은 삭제하지 않고, PC 서버는 모바일 원문 접근 대체가 확인될 때까지 유지한다.

## 4. 5단계 개시 시 추가로 확보할 자료

- Windows 로컬 3단계 검색기 소스 ZIP **확보됨**: 이 대화의 `pdf-library.zip`(Python/WPF 12개 파일). 실제 E: 드라이브의 운영 사이드카와 PDF, 2026-11-01 시점 백업에 해당하는 최신 서버 버전은 여전히 로컬 확인 필요.
- Windows가 읽기 전용으로 내보낸 PDF ID–bookId–루트–사본 개수 매핑과 검산 결과(전체 원본 파일을 업로드할 필요 없음).
- 운영 전 안전한 별도 Neon 시험 DB/브랜치 및 외부 백업·복원 확인 결과.
- 표지 파일 자체는 XML에 없다. 표지 후보는 신뢰 가능한 이미지 출처를 별도로 확인하고, 잘못된 판본을 자동 채우지 않는다.

## 5. 2026-11-03 사용자 제공 소스 분석과 공통 검증 게이트

- `pdf-library.zip`의 `manifest.py`는 **HTTP 전송 없는 MockCatalog**다. 서버 API v2와 필드명이 다르고, Python `digest(rows)`는 `sort_keys=True`인 객체 배열 JSON을 해시한다. 서버가 요구하는 문서 ID 오름차순 **고정 위치 배열**의 `desktopItemsDigest`와는 동일하지 않다. 단순히 URL/인증키만 연결하면 seal 단계에서 충돌할 수 있다.
- PC Codex는 최신 소유자 도서 버전 정보를 검증한 후 `rootsAvailable`, `expectedDocuments`, `copiesByRoot`로 변환하고 `itemsDigest`를 서버 규격대로 새로 계산한다. 스캔 결과 불일치나 버전 충돌 시 업로드·seal·실제 적용을 중단한다.
- PC Codex 결과 보고서는 **비밀과 로컬 경로를 제거한** `검산-summary.json`(건수, 누락 수, digest, HTTP 응답 상태)과 변경 커밋·시험 출력으로 전달한다. ChatGPT는 그 결과와 GitHub 서버 코드·Neon 시험 DB를 대조한다. 서로 다른 환경이 같은 E: 드라이브를 직접 공유한다고 가정하지 않는다.
- 5단계는 (1) 서버/API 코드/DB 백업 검증, (2) Windows 어댑터 로컬 개발·재스캔, (3) 양쪽 manifest 비교, (4) 로고스 2,418건 dry-run, (5) 백업 복원 시연과 사용자 승인, (6) 운영 등록·가역 보관, (7) 타 기기 동기화·원문 열람 검수 순서로 수행한다.
