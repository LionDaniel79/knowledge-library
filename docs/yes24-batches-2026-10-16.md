# YES24 소장 자료 보완

사용자 요청: 시간 간격을 두고 2,000건씩 수집한다. 기존 소장 도서와 도서 PDF만 대상으로 하며 논문·간행물은 제외한다.

## 실행 결정

- 기존 승인된 개발 작업의 수집기 확장으로 진행한다. 현재 feat/library-mvp에서 관련 파일만 추가·수정한다.
- 2,000권 단위, 묶음 사이 10분, API 요청 사이 최소 1.1초. 책 수와 API 호출 수를 별도 기록한다.
- ISBN 조회 → ISBN·제목 확인 → 부족한 서지·표지 URL·목차·소개 발췌를 출처와 함께 보관한다. 원래 책 정보, 개인 메모, 독서 기록은 덮어쓰지 않는다.
- ISBN 미확인 자료는 제목 검색 후보로 남긴다. 제목이 같다는 이유로 판본을 확정하거나 소장본을 합치지 않는다.
- API 키는 환경 파일에서만 읽는다. 오류 응답은 미발견으로 캐시하지 않는다. 401/403/429 등 제공자 거절 시 중지한다. 호출 우회나 키 교체는 하지 않는다.
- E:에 결과·체크포인트·호출 기록을 저장한다. 중단 후 동일 작업 재개 시 캐시와 체크포인트를 이용한다.
- 시간 간격과 일일 한도 준수는 약관의 체계적 DB 축적 제한을 해소하지 않는다. 이 위험은 사용자에게 안내했고, 사용자가 수집 진행을 요청했다. 제공자의 별도 저장 허가를 받았다고 주장하지 않는다.

## 검증 / 진행

- 테스트부터 작성: 다른 ISBN/판본 배제, 거절 응답과 빈 결과 구별, 논문·간행물 배제, 묶음 대기, 출처 저장과 원자료 보존.
- 소량 실조회 및 DB 확인 후 전체 작업을 숨김 프로세스로 실행한다.
- 완료 여부는 status.json과 DB 확인 결과로 보고한다. 시작만 하고 전체 완료로 표시하지 않는다.

## 실행 검증 기록

- 실제 표본 5권: API 6회, 2권에 보강 항목 4건 저장, 판본 검토 후보 3권. 메모 157건·독서기록 419건의 전체 행 지문이 작업 전후 동일했다.
- 별도 검토에서 발견한 중단 후 잠금 복구, 작업 폴더 간 공용 호출 한도, 실제 요청 시작 시각 기준 간격, 잘못된 응답 필드형 검증을 보완했다.
- Ruling: 단일 PC의 모든 YES24 수집기는 기존 `CATALOG_API_USAGE_PATH`의 SQLite 잠금/호출 장부를 공유한다. 종료된 프로세스의 잠금은 트랜잭션 안에서 회수하며 살아 있는 프로세스는 중복 실행하지 않는다. 공유 경로를 임의 변경하지 않는다.
- Ruling: 호출 한도는 설정값과 20,000 중 작은 값이며 보수적으로 최근 24시간을 센다. 이것은 제공자의 날짜 기준 초기화와 별개의 수집기 보호 장치다. 다른 앱에서 사용한 호출량은 알 수 없으므로 제공자의 429 응답도 즉시 중지 조건이다.
- 최종 단위 테스트 76개 파일 / 257건 통과, TypeScript 검사 통과. 중단된 자식 프로세스의 잠금 회수와 살아 있는 작업 중복 실행 거부도 실제 프로세스로 검사했다.
- 전체 수집은 숨김 Node 프로세스로 시작했다. 작업 폴더: `E:/지식서재 작업/private-data/operations/yes24-batch-20261016`. `status.json`은 처리 권수·API 호출 수·묶음 대기 시각을, `results/`는 책별 보완 결과·검토 후보를 보관한다.
- 실제 DB 확인(2026-10-16 17:36 KST): YES24 보강 서지 16건·목차 16건 저장, 메모와 독서기록의 전체 행 지문 동일. 이는 진행 중 표본이며 전체 완료 결과가 아니다.

## 다시 실행 / 중지

기존 작업을 재개할 때 같은 저장 폴더를 사용한다. 이미 실행 중이면 공용 잠금이 중복 실행을 거부한다.

```powershell
& 'C:/Program Files/nodejs/node.exe' --env-file=.env.local --import tsx scripts/collect-yes24.ts --dir 'E:/지식서재 작업/private-data/operations/yes24-batch-20261016' --apply
```

위 명령은 지식서재 소스 폴더에서 실행한다. 작업 폴더에 `STOP`이라는 빈 파일을 만들면 다음 API 요청 또는 묶음 대기 확인 시 중지한다. 재개 전 본인이 만든 `STOP` 파일만 제거한다. 수집기는 Windows 자동 시작에 등록하지 않았다. PDF 연결 서버 시작 바로가기와는 별도의 일회성 작업이다.
